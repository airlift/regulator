# Engine map

This map lists the engines and kernels Regulator has, how one is chosen for
each operation, and what runs when it declines. [Why Regulator is
fast](../WHY_FAST.md) explains the mechanisms for a reader, and the
[optimization catalog](OPTIMIZATION_CATALOG.md) describes each optimization
and credits its origin; this map gives the selection order and the fallbacks,
and links the catalog instead of repeating it. The
[reverse DFA](REVERSE_DFA.md), [memory usage](MEMORY_USAGE.md), and
[scan plan](../benchmarks/SCAN_PLAN.md) references cover those parts in depth,
and the [decision records](../../REGULATOR_DECISIONS.md) explain why each
threshold and trade-off is what it is.

Code references are `Class.method` names in
`src/main/java/io/airlift/regulator`. `CompiledPattern` is abbreviated `CP`
and `RegexpMatcher` `RM`.

## How a route is chosen

A route is decided in five layers. Each later layer works inside what the
earlier ones chose.

| Layer | Decides | Where |
|---|---|---|
| Front end | Trino regular expressions and LIKE pick their own classes before or instead of the shared analysis | `TrinoRegexp.compile`, `TrinoLikePattern.compile` |
| Analysis | The programs, the optional plans and matchers that fit the memory budget, the boolean plan kinds, and one shape | `CP.buildWithProgram`, `CP.selectRoutes` |
| Shape class | Which operations a pattern answers on its own route; each language's compiled-pattern class is sealed, with subclasses for the shapes | `Re2.create`, `JavaRegexp.create`, `RustRegexp.create`, `TrinoCompiledPattern.create` |
| Per-search gates | Input-length thresholds, required-byte rejects, and the sentinels a route returns when it declines | each route |
| Matcher state | Per-matcher routes and state that adapts across finds | `RegexpMatcher` |

Two things cut across the layers. Opt-in generated bytecode replaces the
scan-plan routes of a pattern, or the whole of a LIKE pattern's `matches`,
with a hidden class ([Generated classes](#generated-classes)). Whether the JVM
has the Vector API module changes which routes compilation admits, not only
how fast they run ([Vector API](#vector-api)).

Every route returns what the ordinary engine would return. A route that cannot
answer returns a sentinel and the caller continues on the next route:
`Dfa.CANDIDATE_SEARCH_FALLBACK`, which `LiteralAlternationSpanMatcher.DECLINED`,
`FixedWidthByteSpanMatcher.BAILED`, and the inner and window literal searches'
`FALLBACK` alias; `Dfa.CANDIDATE_SEARCH_QUIT`; a scan plan's handoff offset;
`Dfa.SEARCH_FAILED`; `Dfa.BOOLEAN_SEARCH_SKIPPED`; `Dfa.COUNT_BAILED`; and
`Dfa.COUNT_UNSUPPORTED`. None of them means no match.

### Memory budget

Each compiled regular expression has one budget, 24 MiB by default
(`Re2.Options.DEFAULT_MAX_MEMORY`); [Memory usage](MEMORY_USAGE.md) describes
what it covers. Compilation splits it as RE2 does:

- The forward share is two thirds (`CP.forwardMemory`). The forward program is
  compiled in it, and what the program leaves is its DFA allowance
  (`Prog.dfaMemory`). Every optional plan and matcher is charged against that
  allowance, in the order [Analysis](#analysis-buildwithprogram) lists, so each
  sees what the earlier ones left. With a [lowered boolean
  program](#lowered-boolean-program), the pattern's own program keeps no DFA
  allowance and the lowered program holds the rest; the transparent start
  literal and folded start run, restored OnePass tables, required bytes, and
  prefix literal sets are charged to it, while the position automaton still
  charges the pattern's own program.
- The reverse share is one third. An inner or window literal search takes its
  memory from it first; the reverse program, compiled lazily on first need,
  gets the rest (`CP.reverseProgramMemory`).

An optional route is admitted by one of three rules:

| Rule | Admitted when | Code |
|---|---|---|
| Fits | Its size is at most the remaining DFA allowance | `size <= dfaMemory()` |
| Yields | It fits, and every forward first-match or longest-match DFA that would initialize without it still initializes | `CP.tryReserveBesideForwardDfas`, `CP.costsDfaInitialization` |
| Leaves minimum | It fits, and leaves each forward DFA at least its minimum memory (start-byte tables excluded), whether or not those DFAs would otherwise initialize; when the DFA cannot run the program's assertions, only the fit applies | `Prog.leavesDfaMinimum` |

An optional route that is not admitted is dropped and the pattern compiles
without it. Compilation throws `RegexpCompileMemoryLimitException` only when
the program itself, its simplification, its capture-search plan
(`Nfa.planCaptureSearches`), or the shift table of an exact literal or
accelerated prefix does not fit, and no route without the matching program can
stand in for it ([Compile failure routes](#compile-failure-routes)).

### Vector API

`VectorSupport.isAvailable` is true when the `jdk.incubator.vector` module is
in the boot layer and the preferred byte vector has 16 to 64 lanes. Without
it, every kernel has a scalar or word-at-a-time (SWAR) form, and compilation
also admits fewer routes:

- no DFA [start literal filter](#start-literal-filter) or
  [start class filter](#start-class-filter)
  (`Dfa.DfaInstance.StartLiteralFilterSelection.select`,
  `Dfa.buildStartClassFilter`);
- no prefix literal set (`Prog.configurePrefixAccelBytes`);
- no folded literal alternation (`LiteralAlternationSpanMatcher.analyzeFolded`)
  and no Trino full-case-fold alternation;
- no fixed-width block search and no literal-set root skip;
- no folded inner literal without a searched head: exact leading bytes other
  than a single letter, digit, or whitespace byte.

With 64-lane preferred vectors (such as x86 with AVX-512), compilation drops a
no-prefix folded run that starts every match (`Compiler.foldedRunForAccel`),
the window literal search steps aside for a one- or two-literal start filter
(`WindowLiteralSearch.analyze`), and a rare start set may take a two-literal
[start literal filter](#start-literal-filter).

## Compile-time selection

### RE2, Java, and Rust

| Language | Entry | Analysis | Pattern flags |
|---|---|---|---|
| RE2 | `Re2.compile` → `Re2.compileParsed` | `CP.build`, with the longest-match option | `LATIN1` for Latin-1 encoding |
| Java | `JavaRegexp.compile` | `CP.analyzeParsed`, leftmost-first | none beyond the parse |
| Rust | `RustRegexp.compile` | `CP.analyzeParsed`, leftmost-first | `RUST_SEARCH`, and `LATIN1` in bytes mode |

`RUST_SEARCH` turns on the matcher's Rust empty-match rules. RE2's longest-match
option turns off the scan plan, the compact class counter, the matcher's
class-repeat counter (a single large class is still accepted), the tagged
alternation program, the inner and window literal searches, the transparent
start literal, the literal alternation and literal set (with or without a
program), the anchored submatch route, direct BitState capture, and the
matcher cursors.

#### Analysis (`buildWithProgram`)

`CP.buildWithProgram` compiles the program and admits optional routes in this
order. A route's "Admitted when" cell also names the earlier routes that
exclude it.

| # | Route | Admitted when | Rule |
|---|---|---|---|
| 1 | [Compact class counter](#class-run-counter) | Not longest-match; a large Unicode class repeat, or a class-run alternation with captures (`CP.compactRouteRegexp`, `BoundedCharacterClassCounter.analyzeCompactRoute`); counter plus a placeholder program within the forward share. Returns at once with shape `CLASS_RUN`; a [retained count DFA](#retained-class-count-dfa) may be kept beside it | fits |
| 2 | [Required prefix](#required-prefix) | The pattern is a concatenation of one or more start-of-text anchors followed directly by a literal (`Regexp.requiredPrefix`); a multiline `^` or a capture before the literal gives none, and a Trino full-case-fold literal qualifies only if its folds stay within ASCII | — |
| 3 | Forward program | Always, from the suffix after any required prefix (`Compiler.compileNormalizedDeferringPrefixLiteralSet`); prefix acceleration and the folded prefix run are configured on it, and the required prefix stays on the pattern (`CP.requiredPrefix`) | throws if it does not fit |
| 4 | Final-line OnePass tables released | The program is one-pass only because of a Java or Trino final-line end; restored later if they yield | — |
| 5 | [Exact literal](#exact-literal) | The pattern is one unanchored case-sensitive literal; its prefix scan is configured | throws if the shift table does not fit |
| 6 | [Boolean plan kinds](#boolean-plan-kinds) | Always | — |
| 7 | [Scan plan](#scan-plans), anchored or literal-led | Default scan-plan mode, not longest-match, cannot match empty, `ScanPlan.analyze` accepts | fits |
| 8 | [Lowered boolean program](#lowered-boolean-program) | No scan plan; the find plan is general or nullable-start, or the `lookingAt` plan is general; lowering a final-line `$` changes the tree, and the lowered program compiles with no text-dependent assertions or full-case-fold literals | fits beside the program |
| 9 | Scan plan, run-led | The analyzed plan is neither start-anchored nor literal-led, and there is no lowered program | fits |
| 10 | [Tagged alternation program](#tagged-alternation-program) | No required prefix or lowered program; `TaggedAlternationProgram.compile` accepts | own split, below |
| – | Capture-search plan | Always (`Nfa.planCaptureSearches`); the forward share is its allowance | throws when no plan fits |
| 11 | [Word-run matcher](#word-run-matcher) | No required prefix or lowered program; `WordRunMatcher.analyze` | fits |
| 12 | [Whole-input capture plan](#whole-input-capture-plan) | Same, `WholeInputCapturePlan.analyze` | fits |
| 13 | [Disjoint suffix-repeat matcher](#disjoint-suffix-repeat-matcher) | Same, no captures, `DisjointSuffixRepeatMatcher.analyze` | fits |
| 14 | [Inner literal search](#inner-literal-search), else [window literal search](#window-literal-search) | No required prefix, lowered program, exact literal, scan plan, word-run or disjoint matcher; not longest-match. Inner: not the dot-star-literal shape. Window: no inner search and no transparent start literal | reverse share |
| 15 | [Required bytes](#required-bytes) candidate | `RequiredBytes.analyze` finds a literal or up to three bytes every match holds | charged in `selectRoutes` |
| 16 | [Literal search kernel](#literal-search-kernel) | The find plan is `CONTAINS` and the literal has at least 2 bytes | Trino, or a literal over 64 bytes: fits; otherwise yields |
| 17 | [Dot-star literal span](#dot-star-literal-span) | `DotStarLiteralSpanMatcher.analyze` | yields |
| 18 | [Transparent start literal](#transparent-start-literal) and folded start run | `CP.searchesTransparentStartLiteral`, `Prog.buildTransparentStartLiteral`; the run when the DFA runs the program's assertions and the run's probe pair is more than four times rarer than the literal's (`CP.rarerFoldedStartRun`) | leaves minimum |
| 19 | [Literal set](#literal-set) | Not longest-match; `LiteralSetSpanMatcher.analyze` (no captures, more than 64 literals); its root skip is dropped unless both forward DFAs still initialize beside the set measured without its search tables, and its dense rows and skip table are dropped together where they alone cost a forward DFA its initialization | fits |
| 20 | [Ordered literals](#ordered-literals) | Find plan general, no scan plan, every inner gap matches any byte sequence (`CP.createByteGapOrderedLiteralMatcher`); no lowered or tagged alternation program | yields |
| 21 | [Literal neighbors](#literal-neighbors) | Find plan still general, no scan plan, no required prefix, `LiteralNeighborMatcher.analyze`; no lowered or tagged alternation program | yields |
| 22 | [Literal alternation](#literal-alternation) | Find plan general, no scan plan, not longest-match, `LiteralAlternationSpanMatcher.analyze` | fits |
| 23 | [Fixed-width byte span](#fixed-width-byte-span) | Find plan general, no scan plan, no literal-alternation candidate analyzed, no captures, bounded length up to 1,024 bytes, no inner literal of 2 or more bytes, `FixedWidthByteSpanMatcher.analyze`, and the matcher does not step aside for the engine's scans (`CP.yieldsToEngineRoute`) | fits |
| 24 | [Short fixed-width matcher](#short-fixed-width-matcher) | As 23, but beside an inner literal of 2 or more bytes | fits |
| 25 | [Byte run](#single-byte-table-and-byte-run) | Find plan general, no literal-alternation candidate analyzed, no fixed-width candidate left after the step-aside check, no captures, `SingleByteMatcher.analyzeRun` | fits |
| 26 | Required-bytes narrowing | A [one-of set](#required-bytes) of several distinct bytes beside an inner search gets the lesser of that search's minimum (64 bytes beside a short fixed-width matcher) and 256 bytes as its window limit; a single required byte keeps 256, and one the gated one-byte inner search already scans is dropped | — |
| 27 | [Position automaton](#position-automaton) candidate | `PositionNfa.build` accepts the program | charged in `selectRoutes` |

The tagged alternation program compiles in the program's DFA allowance; a
third of what remains goes to its many-match DFA, which must initialize at
compile time, and the rest returns to the program.

#### Boolean plan kinds

`CP.selectBooleanPlans` gives `find`, `lookingAt`, and `matches` each a plan
kind (`BooleanPlanKind`). Only a pattern whose expression is one non-empty
case-sensitive literal with optional gaps gets literal plans, chosen per
operation:

- `find` without gaps takes `EQUALS`, `STARTS_WITH`, `ENDS_WITH`, a final-line
  form, or `LITERAL_SEARCH` by its anchors; with gaps, it takes `CONTAINS` only
  when the pattern is unanchored and every gap is optional.
- `lookingAt` gets no literal plan when the literal has a leading gap.
- `matches` gets one only with at most one gap, on one side, that matches any
  bytes (or any characters under Latin-1).

RE2's UTF-8 `a.*` gets `CONTAINS` for `find`, `STARTS_WITH` for `lookingAt`,
and `GENERAL` for `matches`. Every other plan is `GENERAL`, except that the
empty pattern's `find` is `LITERAL_SEARCH` and a `find` that can match empty
with no required prefix is `NULLABLE_START`. Later analysis relabels a general
or nullable-start `find` as `LOWERED_PROGRAM`
([lowered boolean program](#lowered-boolean-program)), a general `find` as
`ORDERED_LITERALS` ([ordered literals](#ordered-literals)) or
`LITERAL_NEIGHBORS` ([literal neighbors](#literal-neighbors)), and a general
`lookingAt` as `LOWERED_PROGRAM`.

#### Shape (`selectRoutes`)

`CP.selectRoutes` first charges the routes that depend on the final shape, in
order: the matcher [class counter](#class-run-counter), the
[single-byte table](#single-byte-table-and-byte-run), the restored final-line
OnePass tables (yields), the position automaton (yields), the final form of
the required bytes (yields, stepping down from a long-window search to a
short-window reject to none), and last the
[prefix literal set](#prefix-acceleration) (leaves minimum). Then it picks one
`Shape`:

1. A compact class counter gives `CLASS_RUN`.
2. Otherwise the find plan decides: `GENERAL` gives `ENGINE`;
   `LITERAL_SEARCH` gives `EXACT_LITERAL` for a non-empty literal and
   `ENGINE` for the empty pattern; `NULLABLE_START` and `LOWERED_PROGRAM` give
   `ENGINE`; every other plan, `ORDERED_LITERALS` and `LITERAL_NEIGHBORS`
   included, gives `LITERAL_KERNEL`.
3. A single-byte table on a pattern whose find plan is `GENERAL` (a general
   pattern) gives `BYTE_TABLE`.
4. A scan plan gives `SCAN_PLAN`, overriding every shape above, and sets three
   flags: `literalKernelFind` when the shape was `LITERAL_KERNEL` with a
   `CONTAINS`, `STARTS_WITH`, `EQUALS`, or `EQUALS_FINAL_LINE` find;
   `ordinaryShortBooleanMatch` for a general pattern whose assertions the DFA
   runs, when the plan is start-anchored, has a fork (an optional part), and
   has no boolean tail (`ScanPlan.allowsOrdinaryShortBooleanMatch`; see the
   [scan plan reference](../benchmarks/SCAN_PLAN.md#integration)); and
   `singleAttemptCount` for a start-anchored plan with a required prefix or
   start-anchored program.
5. Otherwise a general pattern takes the first of: a literal alternation
   (`LITERAL_ALTERNATION`), a fixed-width matcher (`FIXED_WIDTH`), a byte run
   (`BYTE_TABLE`), or a literal set, which gives `LITERAL_ALTERNATION` when
   `literalSetFind` (the forward longest-match DFA cannot initialize) or
   `literalSetCount` (the set has its skip table, or the forward first-match
   DFA cannot initialize) holds.

A pattern that can match empty always has the `ENGINE` shape. The language's
`create` method maps the shape to its subclass:

| Shape | RE2 class (Java and Rust: same prefix) | Its own entries |
|---|---|---|
| `ENGINE` | `Re2` | none |
| `EXACT_LITERAL` | `ExactLiteralRe2` | `find`, count, `matches`, `lookingAt`, unanchored capture-free `matchInto` |
| `LITERAL_KERNEL` | `LiteralKernelRe2` | `find`, count, `matches`, `lookingAt`, unanchored dot-star `matchInto` and `matchInternal` |
| `LITERAL_ALTERNATION` | `LiteralAlternationRe2`, or `LiteralSetRe2` with no program | `find`, count; the set also `matchInternal` |
| `FIXED_WIDTH` | `FixedWidthRe2` | `find`, count, unanchored `matchInto` |
| `CLASS_RUN` | `ClassRunRe2` | `find`, count, `matchInternal` |
| `BYTE_TABLE` | `ByteTableRe2` | `find`, count |
| `SCAN_PLAN` | `ScanPlanRe2`, and its generated subclass `CompiledScanRe2` | `find`, count, `matches`, `lookingAt`, `matchInternal` |

The RE2, Java, and Rust shape classes are the same apart from their names.
Rust's base class adds the empty-match and character-boundary rules
([Language differences](#language-differences)). `TrinoCompiledPattern.create`
maps `ENGINE` and `LITERAL_ALTERNATION` to Trino's base class and the other
shapes to subclasses.

#### Compile failure routes

When the program does not fit, compilation tries a route that needs no program
before it throws:

- RE2 (leftmost-first), Java, and Rust: a capture-free alternation of more than
  64 literals compiles as a [literal set](#literal-set) with no program
  (`CP.analyzeLiteralSetWithoutProgram`, from `CP.build`) and runs every
  operation on it.
- Trino: the front end takes literal alternations and sets before the
  analysis, and `CP.analyzeParsedForTrino` may build a fixed-width matcher
  with no program (`CP.analyzeFixedWidthWithoutProgram`), as
  [Trino regular expressions](#trino-regular-expressions) describes.

Otherwise the exception reports the least budget compilation can prove the
pattern needs (`CP.requiredProgramBudget`, `CP.withRequiredTrinoBudget`).

### Trino regular expressions

`TrinoRegexp.compile` parses once and takes the first class that applies:

| # | Class | Chosen when |
|---|---|---|
| 1 | [`LiteralAlternationTrinoRegexp`](#literal-alternation) | `LiteralAlternationSpanMatcher.analyze` accepts and the matcher fits the forward share. No program is compiled |
| 2 | [`LiteralSetTrinoRegexp`](#literal-set) | `LiteralSetSpanMatcher.analyze` accepts within the forward share. No program |
| – | analysis | `CP.analyzeParsedForTrino`: a capture-free, non-literal pattern with no required prefix whose fixed-width matcher never bails may compile with no program (`CP.analyzeFixedWidthWithoutProgram`) when no program route would precede the matcher; otherwise `CP.buildWithProgram`. `TrinoCompiledPattern.create` maps the shape to its class |
| 3 | `BeginLineTrinoRegexp` | The pattern is a lone Trino `^` |
| 4 | [`FullCaseFoldAlternationTrinoRegexp`](#literal-alternation) | The plain literal alternation declined and `LiteralAlternationSpanMatcher.analyzeFullCaseFold` accepts a `(?i)` alternation of ASCII literals; reserved with `CP.tryReserveForwardDfaMemory`. Needs the Vector API |
| 5 | [`OrderedLiteralTrinoRegexp`](#ordered-literals) | `CP.createOrderedLiteralMatcher` accepts and `CP.tryReserveForwardDfaMemory` succeeds |
| 6 | [`DotStarLiteralTrinoRegexp`](#dot-star-literal-span) | Analysis kept a dot-star literal matcher |
| 7 | [`ExactLiteralTrinoRegexp`](#exact-literal) | `CP.hasExactLiteralSpan` |
| 8 | [`FixedWidthByteTrinoRegexp`](#fixed-width-byte-span) | `FixedWidthByteSpanMatcher.createTrinoRegexp` returns a matcher that never bails, and that is the retained one if it steps aside for the engine's scans |
| 9 | [`CharacterClassTrinoRegexp`](#class-run-counter) | `CP.hasCharacterClassSpan`: a compact class counter or a class repeat |
| 10 | [`CompiledScanTrinoRegexp`](#generated-classes) | Generated bytecode is on and `ScanKernelGenerator.TrinoRoutes.of` accepts |
| 11 | `TrinoRegexp` | Otherwise |

`CP.tryReserveForwardDfaMemory` hands back the memory charge of the required
bytes and the prefix literal set, charges the route, then charges the required
bytes again with their step-down and decides the prefix literal set last. A
Trino pattern also keeps the analyzed repeat (`SingleByteRepeatMatcher.Repeat`)
of a [single-byte repeat matcher](#single-byte-repeat-matcher), which is built
on first use.

Trino routes match Joni on valid UTF-8. On malformed input every Trino route
returns the ordinary engine's answer, so no route choice changes a result
([Trino regular expressions](languages/TRINO_REGEXP.md)).

### Trino LIKE

`TrinoLikePattern.compile` has no memory budget and no regular-expression
program. Without an escape, `TrinoLikePattern.tryCompileSimpleAscii` handles an
ASCII pattern with no `_` and `%` only at its ends. Otherwise
`TrinoLikeParser.parse` gives literal, `_`-run, and `%` elements; a leading
literal becomes the prefix and a trailing one the suffix, and the middle
decides the strategy:

| Middle | Strategy | Matcher |
|---|---|---|
| empty | `TrinoLikePattern.simplePlan`: no elements, `EMPTY`; one literal, `EQUALS`; a prefix only, `STARTS_WITH`; a suffix only, `ENDS_WITH`; both, `ORDERED_LITERALS`; neither, `CONTAINS` | none |
| one literal | `CONTAINS` | `ContainsMatcher` |
| two or more literals | `ORDERED_LITERALS` | `OrderedLiteralMatcher` |
| has `_`, `LiteralGapMatcher.analyze` accepts | `LITERAL_GAPS` | `LiteralGapMatcher` |
| has `_`, otherwise | `TRINO_WILDCARD` | `TrinoLikeWildcardMatcher` |

`EQUALS`, `STARTS_WITH`, and `ENDS_WITH` with a literal of at most 16 bytes
become `SHORT_EQUALS`, `SHORT_STARTS_WITH`, and `SHORT_ENDS_WITH`. With
generated bytecode, every strategy is eligible
([Generated classes](#generated-classes)). See the catalog's
[Plan per pattern shape](OPTIMIZATION_CATALOG.md#plan-per-pattern-shape) and
[Trino LIKE Frontend](../../REGULATOR_DECISIONS.md#trino-like-frontend).

### Re2Set and FilteredRe2

`Re2Set.Builder.add` parses each pattern with RE2 syntax, so parse errors
surface there, and appends a match marker with its ID. `Re2Set.Builder.build`
compiles the alternation of all of them as one program (`Compiler.compileSet`)
in the whole budget; captures are off. Its many-match DFA gets what the
program leaves and must initialize, or the build throws. An empty set builds
no program.

`FilteredRe2.Builder.add` compiles each pattern as its own `Re2` with its own
budget and builds its prefilter (`Prefilter.fromRegexp`). `build` compiles the
`PrefilterTree`, which keeps atoms of at least the minimum atom length (3 by
default), and builds the atom search: an `Re2Set` in `FIND` mode over the
quoted atoms, with its own budget
(`FilteredRe2.Builder.setAtomSearchMaxMemory`, 24 MiB by default). If the atom
search does not fit, the collection still builds without it.

## Decision flow per operation

This section traces each public operation from its entry to the first route it
runs and each fallback. RE2 and Java share these flows. Rust shares them with
two differences outside bytes mode. Its `findInto` and `findResult`, its ranged
`find`, and a nullable pattern's full-`Slice` `find` run `RustRegexp.search`,
which searches again one byte past an empty match that splits a character.
Its ranged `lookingAt` and `matches` forms, capture forms included, also
require a character boundary at the start. Trino, LIKE, and the multi-pattern
classes have their own.

### find

A full-`Slice` boolean `find` (Trino `contains`) dispatches on the shape:

| Shape | First route | Falls back to |
|---|---|---|
| `ENGINE` | `CP.findOnEngine`, below | the ordinary engine |
| `EXACT_LITERAL` | `CP.findOnExactLiteral`: the program's [prefix scan](#prefix-acceleration) | none |
| `LITERAL_KERNEL` | `CP.findOnLiteralKernel` by find plan: `CONTAINS` on the [literal search kernel](#literal-search-kernel) for windows of at least 64 bytes where the pattern kept one, else `Slice.indexOf`; `EQUALS`, `STARTS_WITH`, `ENDS_WITH`, and the final-line forms by comparison; `ORDERED_LITERALS` on the [ordered-literal matcher](#ordered-literals); `LITERAL_NEIGHBORS` on the [neighbor matcher](#literal-neighbors) | neighbors only: `findOnEngine` when the matcher is undecided, or on a long window whose required literal hands off to the inner literal search |
| `LITERAL_ALTERNATION` | `CP.findOnLiteralAlternation`: the [trie](#literal-alternation), or the [literal set](#literal-set) when `literalSetFind` | trie `DECLINED`: the ordinary engine; no trie and no `literalSetFind`: `findOnEngine` |
| `FIXED_WIDTH` | `CP.findOnFixedWidth`: [fixed-width span](#fixed-width-byte-span) | `BAILED`: `findOnEngine` |
| `CLASS_RUN` | `CP.findOnClassRun`: [class-run counter](#class-run-counter) | none |
| `BYTE_TABLE` | `CP.findOnByteTable`: on input of at most 64 bytes, the [byte run or single-byte table](#single-byte-table-and-byte-run) | longer input: the ordinary engine, whose DFA scans for the bytes |
| `SCAN_PLAN` | `CP.findOnScanPlan`, below | handoff: the ordinary engine from the handoff offset |

`CP.findOnEngine` runs these steps in order; each answers or falls through:

1. A gated one-byte [inner literal search](#inner-literal-search) that checks
   short windows, on a pattern with no required bytes, runs first
   (`CP.findsInnerLiteralFirst`, `CP.findOnInnerLiteralSearch`). Its fallback,
   `CP.findAfterInnerLiteralFallback`, runs the DFA with
   [slow-reset](#when-the-dfa-fails) judging, then the
   [position automaton](#position-automaton) if the DFA is skipped, or the
   submatch engines if it fails.
2. With [required bytes](#required-bytes), a window shorter than their window
   limit (256 bytes for most forms) is rejected when its first byte cannot
   start an anchored match, when it is shorter than the minimum match, or when
   it lacks the bytes. A longer window either hands the required literal's
   first hit to the inner literal search (`CP.findFromRequiredLiteral`) or is
   rejected when it lacks the literal (`CP.longWindowLacksRequiredLiteral`).
3. A nullable pattern with no text-dependent assertions whose DFA can return an
   empty match at the start answers true
   (`CP.canReturnEmptyAtStartForBooleanMatch`).
4. Otherwise the [ordinary engine](#the-ordinary-engine) runs, unanchored, on
   the [lowered boolean program](#lowered-boolean-program) if there is one,
   else on the forward program.

`CP.findOnScanPlan` runs these steps in order; each answers or falls through:

1. `literalKernelFind`: `findOnLiteralKernel`.
2. `ordinaryShortBooleanMatch` and input of at most 48 bytes: the ordinary
   engine.
3. A start-anchored plan: `CP.matchStartAnchoredScanPlan`, after rejecting
   input longer than the maximum span.
4. An unanchored plan that is not literal-led: the short-window required-bytes
   reject.
5. A plan that allows the ordinary boolean search: `CP.findWithOrdinaryHandoff`,
   which runs the plan until its failed attempts are dense or exceed its work
   budget, then hands off.
6. Otherwise `CP.searchScanPlan`, and `CP.finishScanSearch` continues a handoff
   on the ordinary engine.

A generated scan-plan class skips step 2 and checks the plan's own required
literal in place of step 4.

### matches and lookingAt

A full-`Slice` `matches` or `lookingAt` of an `EXACT_LITERAL` pattern compares
directly. Otherwise the operation's plan kind decides. A literal plan kind
answers by comparison (`CP.matchLiteralPlan`), and a `LOWERED_PROGRAM`
`lookingAt` runs the ordinary engine on the lowered program, anchored at the
start (`CP.matchLoweredBooleanProgram`). A `GENERAL` plan of a `SCAN_PLAN`
pattern uses `CP.matchOnScanPlan` (a start-anchored plan's executor, or one
anchored attempt of an unanchored plan; neither hands off), or in a generated
class that class's own `matches` and `lookingAt`; a `GENERAL` plan of any
other shape goes through [captures](#captures-and-one-shot-calls) with an
anchor. The ranged forms always go through captures.

### Captures and one-shot calls

A call searches its region and reads its context, the part of the input its
anchors and assertions see: the whole input for a ranged call, and the region
for a matcher, with the exceptions [Matching
APIs](REGULATOR_API.md#matching-apis) gives.

`findInto`, `lookingAtInto`, `matchesInto`, their `Result` forms (`findResult`,
`lookingAtResult`, `matchesResult`), ranged `find`, `matches`, and
`lookingAt`, and RE2's `replaceFirst` and `extract` all enter `CP.matchInto`:

1. Three shapes answer an unanchored call on their span route:
   `EXACT_LITERAL` with no capture groups (`CP.oneShotExactLiteral`),
   `LITERAL_KERNEL` with a dot-star literal (`CP.oneShotDotStarLiteral`), and
   `FIXED_WIDTH` (`CP.oneShotFixedWidth`, falling through on `BAILED`).
2. An unanchored call over at least 256 bytes runs
   `CP.longWindowLacksRequiredLiteral`: a window that lacks the required
   literal or [one-of bytes](#required-bytes) holds no match.
3. `CP.matchRegionInto` calls `matchInternal`. When the caller's buffer is
   wider than the pattern's groups and at most 64 slots are needed, it
   allocates a smaller buffer filled with `-1` and sets the caller's slots past
   it to `-1`; `matchInternal` writes into the smaller buffer, and the result
   is copied back, so OnePass is not turned away.
4. `matchInternal` runs the shape's own engine where it has one, and the
   [ordinary engine](#the-ordinary-engine) for every other call and every call
   these decline:
   - `CLASS_RUN`: the class-run counter.
   - A literal-alternation pattern with no program: the literal set.
   - A Trino `FIXED_WIDTH` pattern compiled with no program: the fixed-width
     matcher, anchored or not (`CP.matchInternalOnFixedWidth`).
   - An unanchored `LITERAL_KERNEL` call: the dot-star literal span.
   - `SCAN_PLAN`: the plan (`CP.matchInternalOnScanPlan`), for a call of the
     forward program whose region ends at the context end
     (`CP.reachesScanPlan`). A start-anchored plan answers false for a region
     that starts after the context start. Two unanchored boolean calls run the
     ordinary engine instead: one on a plan that allows the ordinary boolean
     search, and one of at most 48 bytes with `ordinaryShortBooleanMatch`.

This path makes no short-window required-bytes check. Full-`Slice` `find`,
unanchored scan-plan `find`, and matcher finds make it
([Short-Window Required Bytes Reject](../../REGULATOR_DECISIONS.md#short-window-required-bytes-reject)).

### count

`CP.count` returns 0 for input outside the pattern's
[span-length bounds](#match-length-rejects), then calls the shape's
`countMatches`. A negative result means only a matcher can count: `count` runs
a [group-zero matcher](#matcher-iteration) loop as an
[all-match operation](#match-start-set), and after `COUNT_BAILED` it marks the
matcher to skip the forward DFA.

| Shape | Route | Falls back to |
|---|---|---|
| `ENGINE` | `CP.countOnEngine`: the disjoint suffix-repeat matcher's count; `-1` for a nullable pattern or one with DFA-unsupported assertions; one attempt for a start-anchored pattern or one with a required prefix; the [class-run counter](#class-run-counter), which defers to the DFA for sparse single members; then `CP.countDfaMatches` | matcher loop |
| `EXACT_LITERAL` | `CP.countOnExactLiteral`: prefix-scan loop | none |
| `LITERAL_KERNEL` | the dot-star literal's count | `countOnEngine` |
| `LITERAL_ALTERNATION` | the trie's `countOrDecline`, or the literal set's count when `literalSetCount` | `DECLINED`: `countDfaMatches`; otherwise `countOnEngine` |
| `FIXED_WIDTH` | `countOrBail` | `countOnEngine` on the rest after a bail |
| `CLASS_RUN` | the [retained class count DFA](#retained-class-count-dfa), else the counter | the counter |
| `BYTE_TABLE` | the single-byte table on input of at most 64 bytes without a byte run | the class counter, else `countDfaMatches` |
| `SCAN_PLAN` | an unanchored plan's search loop (`CP.countUnanchoredScanMatches`); a start-anchored plan with `singleAttemptCount` makes one attempt | handoff: the ordinary engine; other anchored plans: `countOnEngine` |

`CP.countDfaMatches` counts none in a long input that lacks the long-window
literal, then counts on the inner or window literal search when the input
reaches that search's count minimum (`CP.countInnerLiteralMatches`,
`CP.countWindowLiteralMatches`, each handing off to the DFA count near dense
candidates), else on the [short fixed-width
matcher](#short-fixed-width-matcher), else with
[`Dfa.countMatches`](#dfa-counting). A count whose matches all end at the
inner literal's end stops at the reverse DFA
([Inner Literal Counts To The Literal End](../../REGULATOR_DECISIONS.md#inner-literal-counts-to-the-literal-end)).

### forEachMatch and matchers

`forEachMatch` and `matcher` run on [`RegexpMatcher`](#matcher-iteration) in
RE2, Java, and Rust; Trino's run on `TrinoRegexpMatcher`
([Trino operations](#trino-operations)). `CP.forEachMatch` loops a
group-zero matcher's `find` as an all-match operation, which lets a dense
search switch to the [match start set](#match-start-set); no shape overrides
it. A caller's own `find` loop is not an all-match operation and never
switches.

### RE2 replaceFirst, replaceAll, and extract

`Re2.replaceFirst` and `Re2.extract` make one capture call through
`CP.matchInto`. `Re2.replaceAll` checks the required literal near each next
start with a back-off (`CP.nearRequiredLiteralScansInLoop`), and calls
`matchInternal` through `CP.matchIntoAfterLoopCheck`. It uses no
`RegexpMatcher` and skips the shapes' `matchInto` span shortcuts, so an
`EXACT_LITERAL` or `FIXED_WIDTH` pattern runs the ordinary engine for each
match; `matchInternal` shortcuts still apply.

### Trino operations

`TrinoRegexp` runs each operation on the shared compiled pattern unless its
class overrides it:

| Operation | Base route |
|---|---|
| `contains` | the shape's `find` |
| `count` | 0 outside the span-length bounds; the single-byte table at any length; the [single-byte repeat matcher](#single-byte-repeat-matcher); the shape's `countMatches`; a group-zero matcher loop |
| `forEachMatch` | `matcher(source, 0)` loop as an all-match operation; span and generated matchers ignore the all-match hooks |
| `position` | the single-byte repeat cursor, else a group-zero matcher `find` from the start and once per extra occurrence, not as an all-match operation |
| `extract` | a start-anchored scan plan for a nonzero group, without a matcher; for a nonzero group, null when the checks before a matcher reject the input (`TrinoRegexp.captureSearchFailsBeforeMatcher`); else one matcher `find` |
| `extractAll`, `split` | the single-byte repeat cursor; for a nonzero group, no matches when the checks before a matcher fail (`TrinoRegexp.captureSearchFailsBeforeMatcher`); else a matcher loop |
| `replace` with a template | `TrinoReplacementPlan` (the template is cached); the repeat cursor; a group-zero matcher when no group is referenced, else a matcher keeping groups 1 through the highest referenced |
| `replace` with a function | the repeat cursor without captures, else a matcher loop |
| `matcher(source, n)` | the class's span matcher (literal alternation, literal set, fixed width, full-case-fold alternation) or the generated class's `CompiledScanMatcher`; a group-zero matcher for `n == 0`; a deferred matcher when the pattern keeps required bytes and a capture find runs the general search (`RM.captureFindRunsGeneralSearch`: no start-anchored scan plan or anchored submatch route, not Rust), built once a find passes its length and required-byte checks or a result accessor needs it (`TrinoRegexpMatcher.deferredEngine`); else `RegexpMatcher` |

The span classes (literal alternation, literal set, dot-star literal, exact
literal, fixed width, character class) answer `count`, `position`, `extract`,
`extractAll`, `split`, and group-free replacements from their span matcher,
with these exceptions: the exact-literal and character-class classes use
spans for `extract` and `extractAll` only for group zero, and the
character-class class counts through its shape's `countMatches`. The literal
alternation, literal set, fixed-width, and full-case-fold classes also answer
`contains` and `matcher` on their own routes. `BeginLineTrinoRegexp` overrides
only `count`: one plus the line feeds before the last byte.
`OrderedLiteralTrinoRegexp` overrides only `contains`, and falls back to the
engine when a gap is not whole characters
(`OrderedLiteralMatcher.findWithCharacterGaps`).

`FullCaseFoldAlternationTrinoRegexp` chooses between the folded literals and
the ordinary engine per operation and input
([Literal alternation trie](OPTIMIZATION_CATALOG.md#literal-alternation-trie)):

- Where the ordinary engine searches with a
  [start literal filter](#start-literal-filter)
  (`CP.searchesStartLiteralFilter`), input under 1 KiB takes the folded
  literals if it is ASCII and the ordinary engine otherwise, for every
  operation, and longer input runs `count`, `extractAll`, `split`, and
  `replace` on the ordinary engine.
- Without that filter, those four operations check the whole input first.
- Except on input under 1 KiB with the filter, `contains` tries the folded
  literals first and runs the ordinary engine only on input that holds such
  characters, and `position` and `extract` check only up to the longest
  literal's length past the start of the occurrence found, or the rest of the
  input when none is found.

The generated class emits `count`, `position`, `extract`, `extractAll`,
`split`, both `replace` forms, and `contains` where its routes reach the plan
(`ScanKernelGenerator.TrinoRoutes.contains`); its matcher comes from
`CompiledScanTrinoRegexp`. Span loops are not all-match operations, so the
match start set applies only to the engine's matcher loops. The catalog's
[Span-only operations](OPTIMIZATION_CATALOG.md#span-only-operations) has the
details.

### LIKE matches

`TrinoLikePattern.matches` rejects input outside the pattern's length bounds,
answers a `SHORT_*` strategy with up to two word compares (one byte compare
for a one-byte literal;
[`LiteralMatchKernel.matchesShortLiteralAt`](#short-literal-in-two-words)),
and otherwise switches on the strategy: `EMPTY` is true; `EQUALS`,
`STARTS_WITH`, and `ENDS_WITH` compare in place; the others check the prefix
and suffix in place and run the middle's [LIKE matcher](#like-matchers), if
there is one. A generated class emits the same flow with the pattern's data
as constants.

### Re2Set and FilteredRe2 matching

`Re2Set.matchesAny` and `Re2Set.matchingPatternIds` run only the
[many-match DFA](#many-match-dfa); there is no NFA, scan, or prefix route.
`matchesAny` runs the generic DFA search loop (`Dfa.searchMany` with no match
set, which calls `Dfa.search` in `MANY_MATCH` mode), and `matchingPatternIds`
runs its own loop (`Dfa.searchMany` with a match set). As in upstream RE2,
both keep going through repeated cache resets. Either gives up only when a
reset cannot restore its states or compute the next transition, or when the
start state cannot be allocated, and then throws
`RegexpMatchMemoryLimitException` with no partial result.

`FilteredRe2` methods that take atom IDs use the caller's; `matchingPatternIds`
and `firstMatchResult` with only the text run the atom search on the text
after case canonicalization, and throw `IllegalStateException` when the
collection has atoms but its atom search was not built. A collection with no
atoms has no atom search and goes straight to the candidates. Each candidate
pattern, in ascending ID order, then runs its own `Re2.find`, or
`Re2.findResult` for `firstMatchResult`.

## The ordinary engine

`CP.matchOnOrdinaryEngine` is the cascade every regular-expression route falls
back to. It runs these steps in order; each answers or falls through.

1. **Pre-engine matchers:** on the forward program only, the
   [disjoint suffix-repeat matcher](#disjoint-suffix-repeat-matcher) and the
   [word-run matcher](#word-run-matcher) always answer; the
   [whole-input capture plan](#whole-input-capture-plan) answers a search of
   the whole context or continues.
2. **Required prefix:** the match must start at the context start with the
   prefix; the search continues anchored after it.
3. **Anchors:** a start-anchored program rejects a later start, an end-anchored
   one an earlier end; both anchors make a full match.
4. **[Length rejects](#match-length-rejects):** a window under 4 KiB shorter
   than the minimum match; an anchored window longer than the maximum span; an
   anchored first byte that cannot start a match.
5. **Direct BitState capture:** an unanchored search through a matcher that
   asks for groups beyond group zero, on a window from 4 KiB up to the
   program's unanchored BitState limit, of a program that is not one-pass, in a
   leftmost-first pattern, runs one [BitState](#bitstate) pass and returns its
   answer (`CP.canUseDirectBitStateCapture`). A pattern with an inner literal
   search first rejects a window that lacks the literal.
6. **Any-byte full match:** a full match of `\C*`, or Latin-1 `(?s).*`, with
   at most group zero, is true.
7. **Unanchored phase:**
   - A program with DFA-unsupported assertions, a matcher whose
     [quit streak](#matcher-iteration) reached 4 or whose cursor quit (in a
     program whose DFA can quit), or a group-zero search of a matcher marked
     after a bailed count, skips the literal search and the DFA.
   - Otherwise the [inner literal search](#inner-literal-search) runs on a
     window of at least its minimum, else the
     [window literal search](#window-literal-search) on a window of at least 96
     bytes. When the search finds no match, that is the answer; a span it
     finds answers a boolean or group-zero call, and for wider captures it
     becomes the exact range and the DFAs are skipped. `FALLBACK` continues.
   - An end-anchored program runs only the reverse longest-match DFA from the
     window end.
   - Otherwise the forward [DFA](#lazy-dfa) runs. A boolean search uses
     `Dfa.searchJudgingSlowResets` and runs the position automaton when the
     DFA is skipped. The start is the end minus the width for a fixed-width
     pattern, the search start for an empty match there, and otherwise comes
     from the [reverse DFA](#reverse-program).
   - When the DFA was skipped, a window that lacks the inner literal is
     rejected.
8. **Anchored phase:** the anchored DFA is skipped when OnePass can run on a
   window of at most 4 KiB with groups beyond group zero, or of at most
   16 bytes without them, or when BitState can run on the window with groups
   beyond group zero; otherwise the anchored DFA runs and answers a boolean
   call.
9. **Submatch phase:** with an exact range from the DFA or the literal search,
   a submatch engine runs anchored over it; otherwise over the window. A call
   with groups beyond group zero, in a program with text-dependent assertions
   and a [tagged alternation program](#tagged-alternation-program), runs
   `TaggedAlternationProgram.search`; every other call runs
   `CP.runSubmatchEngine`.

`CP.runSubmatchEngine` takes the first engine that applies:

| # | Engine | Condition |
|---|---|---|
| 1 | [OnePass](#onepass) | One-pass program, anchored search, capture slots supported |
| 2 | [BitState](#bitstate) | The window fits the anchored or unanchored BitState text limit |
| 3 | [Position automaton](#position-automaton) | Group zero or boolean, and the program has one |
| 4 | [Pike NFA](#pike-nfa) group zero | Group zero only (`Nfa.searchGroupZero`) |
| 5 | Pike NFA | Otherwise (`Nfa.search`) |

### When the DFA fails

`Dfa.SEARCH_FAILED` means the DFA could not answer: it has no budget or did
not initialize (`Prog.getCachedDfa`), its start state could not be allocated
after a reset, it quit, or, outside a many-match search, its cache made a slow
reset (one after reading fewer than ten bytes per cached state since the
previous reset) and it had no [pointer table](#dfa-step-forms) to give back. A
failed unanchored DFA leaves the window to the submatch phase unanchored, so
OnePass cannot run and BitState, the position automaton, and the Pike NFA
follow. A failed anchored DFA leaves the window to the anchored submatch
engines. In a program whose DFA can quit, each failed unanchored search adds
to the matcher's quit streak.

Three guards skip a DFA that keeps failing across calls
([Thrashing DFA skipped across calls](OPTIMIZATION_CATALOG.md#thrashing-dfa-skipped-across-calls)):
after two bailed counts in a row the next 16 DFA counts return `COUNT_BAILED`
at once; in a program with a position automaton, two slow resets in a row
across boolean searches make the next 65,536 boolean searches return
`BOOLEAN_SEARCH_SKIPPED`; and a tagged alternation program's many-match
searches skip their DFA for the next 65,536 searches after two slow resets in
a row (`Dfa.searchManyFullJudgingSlowResets`).

## Matcher iteration

`RegexpMatcher` runs matcher finds, `forEachMatch`, the `count` fallback, and
the Trino loops that use an engine matcher. `matcher(input, n)` keeps group
zero and the first `n` groups. Its constructor decides these routes and
creates the candidate start cursor; the group-zero forward cursor is built on
first use, and a matcher with a span search creates a candidate cursor the
first time the span search hands a find to the program. The rows marked group
zero serve only a matcher that keeps no groups beyond it:

| Route | Chosen when |
|---|---|
| [Single-byte table](#single-byte-table-and-byte-run) | Group zero; the pattern has one |
| Span search | Group zero; `CP.groupZeroSpanSearch` (a `GroupZeroSpanSearch`): none with a single-byte table or class counter; else the first of the exact literal, literal alternation, literal set, dot-star literal, fixed width, and short fixed width |
| [Class counter](#class-run-counter) | `CP.classMatchCounter`, for group zero or a matcher that keeps the groups of a class-run alternation |
| [Candidate start cursor](#candidate-start-cursor) | Group zero; none of the three above, and `CP.createCandidateStartCursor` builds one |
| [Group-zero forward cursor](#group-zero-forward-cursor) | No class counter, and the matcher keeps only group zero or the pattern has a tagged alternation program; built on first use |
| Start-anchored [scan plan](#scan-plans) | Any matcher; no single-byte table and the plan is start-anchored |
| Lowered searches | The pattern has a [lowered boolean program](#lowered-boolean-program): the lowered candidate start for any matcher, the direct lowered group-zero search for group zero |

`RM.find` takes the first route that applies: the start-anchored scan plan,
which answers only the first find; the span search (`RM.findSpanSearch`); the
anchored submatch route for a capture matcher's first find of a whole input;
`RM.findRust` for Rust; else `RM.findGeneral`. The anchored submatch route
(`CP.hasAnchoredSubmatchRoute`) needs one of the base classes `Re2`,
`JavaRegexp`, `RustRegexp`, or `TrinoCompiledPattern`
(`CP.isOrdinaryEngineClass`), and a start-anchored program that is one-pass
or fits BitState, with a non-zero minimum length; no pre-engine matcher,
required prefix, longest match, scan plan, or literal set; and not a tagged
program with text-dependent assertions. `CP.matchAnchoredSubmatch` runs
OnePass on at most 4 KiB when it supports the requested capture slots;
BitState within its anchored limit when OnePass does not support them; and
otherwise the ordinary engine, including for a one-pass search longer than
4 KiB.

A literal alternation with at least 64 bytes left hands off to the program:
the candidate cursor, created on the first handoff, where its literals differ
in length, and the group-zero forward cursor where they share one. A
fixed-width matcher that bails hands off the same way. A short fixed-width
matcher steps aside for the inner literal search when the window reaches that
search's minimum.

A matcher keeps adaptive state across its finds, and a matcher reset clears
it: the quit streak, which counts failed unanchored searches in a row of a DFA
that can quit (`DFA_QUIT_STREAK_LIMIT` is 4); the cursor-quit mark for the
current find; the skip-forward-DFA mark set by `count` after `COUNT_BAILED`;
the long-window literal occurrence and its near-literal scan back-off; and
any match start set it holds.

`RM.findGeneral` runs these in order:

1. The minimum-length and maximum-span rejects and the short-window
   required-bytes reject; then the long-window required-literal check. Later
   finds reuse the occurrence it found, and after 8 scans in a row that find
   the literal within 256 bytes, the check stops scanning until the matcher is
   reset.
2. A Rust search of a partial region runs with the whole input as context and
   skips the routes below; a non-empty Java region that starts on the line
   feed of a CR LF, in a pattern with no required prefix and a Java end
   assertion (`$`, `(?m)$`, `\Z`) compiled without `UNIX_LINES`, runs the
   Pike NFA told that a carriage return precedes it.
3. The single-byte table with fewer than 64 bytes left; the class counter; an
   empty match at the start of a nullable pattern with no capture groups and
   no text-dependent assertions, when its DFA initializes, supports the
   nullable start-byte check, and sees the context end or a first byte that
   cannot start a match (`Dfa.canReturnEmptyAtStart`).
4. The candidate start cursor, then the group-zero forward cursor (or the
   match start set when one is held), each skipped when the inner literal
   search will run, when the matcher was marked after a bailed count, or when
   the quit streak reached 4 on a quitting DFA; the forward cursor is also
   skipped when this find's candidate cursor quit.
5. The direct lowered group-zero search and the lowered candidate start.
6. `CP.matchRegionInto`, which reaches `matchInternal` and the
   [ordinary engine](#the-ordinary-engine) with the matcher as its workspace.

`RM.matches` and `RM.lookingAt` skip the boolean plans and enter
`CP.matchRegionInto` over the region with the matcher's workspaces. Rust uses
the whole input as context, after rejecting a region start inside a UTF-8
character outside bytes mode; a Java region that starts on the line feed of a
CR LF, as in step 2, runs the Pike NFA told a carriage return precedes it
(`CP.matchRegionAfterCarriageReturnInto`).

### Match start set

An all-match operation (`forEachMatch`, the `count` fallback, Trino's iterating
operations) lets its matcher switch when the matcher keeps only group zero, has
the group-zero forward cursor, has no single-byte table or span search, and its
region is at least 4 KiB (`RM.beginAllMatchOperation`). At the 64th cursor
find, if those finds advanced at most 64 bytes each on average, at least 4 KiB
remain, and `CP.switchesToMatchStartSet` holds, `Dfa.collectMatchStarts`
collects every match start in the rest of the region in one reverse many-match
pass into a bitset of at most 1 MiB, borrowed from the reverse longest-match
DFA's free memory. Later finds take the next start from the set and find the
end with an anchored forward DFA (`CP.findOnMatchStartSet`). Any failure
releases the set and returns to the cursor. A `count` reaches this only when
its shape cannot count, which leaves mainly patterns that can match empty and
hold empty-width assertions the DFA runs. See
[Match start set for dense all-match searches](OPTIMIZATION_CATALOG.md#match-start-set-for-dense-all-match-searches),
[Match Start Set for Dense All-Match Searches](../../REGULATOR_DECISIONS.md#match-start-set-for-dense-all-match-searches).

## Engines and kernels

One entry per engine or kernel: what it does and, where they apply, when it is
chosen, what bounds it, and what runs when it declines. The catalog link gives
the mechanism and its origin, and a decision link the reasons behind it.

### Automata

#### Lazy DFA

RE2's lazy DFA, built state by state while it searches and cached per program
and kind, shared by every thread searching the pattern.

- **Kinds:** `FIRST_MATCH` for forward searches that want the leftmost-first
  end; `LONGEST_MATCH` for boolean (earliest-match) searches, longest-match and
  full-match searches, end-anchored programs, and the ordinary reverse
  boundary searches; `MANY_MATCH` for `Re2Set`, the tagged alternation
  program, and the match start set's reverse pass (`Dfa.DfaInstance.Kind`). A
  count uses `FIRST_MATCH`, or `LONGEST_MATCH` for a longest-match pattern or
  an end-anchored program.
- **Chosen:** by the ordinary engine, the counts, the cursors, and the literal
  searches' confirmations; never for a program with DFA-unsupported assertions:
  Java's `$`, `\Z`, `(?m)^`, and, outside `UNIX_LINES`, `(?m)$`, and Trino's
  `$`. For boolean calls, the [lowered boolean
  program](#lowered-boolean-program) may rewrite a terminal Trino `$`, and
  Java's `$` and `\Z` under `UNIX_LINES`, so the DFA can run them.
- **Bounds:** `Prog.dfaBudget` gives each forward kind half the program's DFA
  allowance, a reverse longest-match DFA all of the reverse program's, and a
  many-match DFA all of its program's, except the match start set's, which
  borrows half the reverse longest-match DFA's free state memory. A DFA that
  cannot hold 20 states does not initialize. State tables start at up to
  256 rows and grow only as far as the budget funds. A full cache resets; when
  a state does not fit, the DFA first refunds paired rows, then recalls a
  match-start-set loan, then gives its [pointer table](#dfa-step-forms) back.
- **Falls back:** `SEARCH_FAILED`
  ([When the DFA fails](#when-the-dfa-fails)), `COUNT_BAILED`, or
  `COUNT_UNSUPPORTED`.
- **Word assertions:** a program with a Rust Unicode word assertion or a Java
  or Trino word boundary decodes characters on the DFA and quits only on
  malformed UTF-8 it has claimed as a character.
- **Concurrency:** searches read one published table generation without a
  lock; one that needs a missing state reruns holding the cache lock.
- **Catalog:** [Object rows with an integer sidecar](OPTIMIZATION_CATALOG.md#object-rows-with-an-integer-sidecar),
  [State tables that start small](OPTIMIZATION_CATALOG.md#state-tables-that-start-small),
  [Assertions on the DFA with lazy quit](OPTIMIZATION_CATALOG.md#assertions-on-the-dfa-with-lazy-quit),
  [Unicode word assertions decided on the DFA](OPTIMIZATION_CATALOG.md#unicode-word-assertions-decided-on-the-dfa),
  [Copy-on-reset readers](OPTIMIZATION_CATALOG.md#copy-on-reset-readers).
- **Decision:** [Memory Budgets And DFA Caching](../../REGULATOR_DECISIONS.md#memory-budgets-and-dfa-caching),
  [Shared DFA Concurrency](../../REGULATOR_DECISIONS.md#shared-dfa-concurrency).

Inside `Dfa.search`, a forward search takes the first route that applies: a
single-byte prefix loop; the [prefix scan](#prefix-acceleration); an anchored
long-prefix integer loop for a case-sensitive required prefix of at least
16 bytes; [fixed-distance byte candidates](#start-byte-scans) on at least
4 KiB; the [pointer table](#dfa-step-forms) for a short search once the DFA has
seen 16 short searches; a [start-byte scan](#start-byte-scans); the [paired
table](#dfa-step-forms) on at least 256 bytes; then `Dfa.searchForward`. There
an end-anchored or full-match search of at least 64 KiB samples
[self-loops](#self-loop-exit-byte-scans) first; otherwise a search from a
non-matching start runs on the pointer table, requested with at least 256 bytes
left and used at any length once one covers the start; anything else steps the
object rows.

#### DFA step forms

Every DFA state is an object row whose slots reference the next rows, with an
integer sidecar; these rows are authoritative, and every other form falls back
to them.

- **Pointer table:** a table of 64-bit entries
  (`Dfa.DfaInstance.requestAbsolutePointerTransitions`), native memory with
  native access and a `long[]` otherwise. Requested by forward searches of at
  least 256 bytes from a non-matching start, count self-loop handoffs, reverse
  longest searches, and short searches after 16 of them; allocated by an
  exclusive search (one that holds the cache lock) within the budget; never
  for many-match DFAs. Given back for the DFA's life on a slow reset, or when
  a state does not fit and the table's rows cost at least a quarter of the
  retained Java state memory: at once if refunding the table makes room for
  the state, otherwise on the next such state with no other reset between.
  [Absolute-pointer table](OPTIMIZATION_CATALOG.md#absolute-pointer-table),
  [Bounded DFA Pointer Transition Table](../../REGULATOR_DECISIONS.md#bounded-dfa-pointer-transition-table).
- **Paired table:** composed two-byte transitions
  (`Dfa.DfaInstance.rebuildPairedTransitions`) for forward searches and counts
  of at least 256 bytes. The whole table within 64 KiB of object rows, or
  32 KiB as one flat table on aarch64; otherwise two selected rows within
  16 KiB, or 8 KiB flat. Never for reverse or many-match DFAs, and never beside
  a pointer table. Turned off after 16 first-match paired searches in a row
  whose decoded pair match ends fewer than 16 bytes from the search start;
  other outcomes leave that streak unchanged, and counts keep their own.
  [Bounded paired table](OPTIMIZATION_CATALOG.md#bounded-paired-table),
  [Bounded Paired DFA Transitions](../../REGULATOR_DECISIONS.md#bounded-paired-dfa-transitions).

#### Self-loop exit-byte scans

With the Vector API, a state that loops on itself can scan ahead to the next
byte that leaves it. A state qualifies in one of three forms: the exit form,
with one to three exit bytes; the high-byte exit form, every non-ASCII byte
plus up to three ASCII bytes; or the stay form, up to four stay ranges. The
scans run in counts from a non-matching start, not end-anchored, with at least
64 bytes left (re-arming with a growing distance after unproductive scans, and
stopping after 8 unproductive searches in a row); in matching forward loops
after 32 stepped bytes; in unbounded reverse searches of at least 64 bytes
from a non-matching start, not earliest-match, that reach the loop within
their probe steps (exit form only); and in end-anchored or full-match searches
of at least 64 KiB whose first 64 transitions are at least 90% self-loops, on
non-matching loops only and not the high-byte exit form.
[Self-loop exit-byte scan](OPTIMIZATION_CATALOG.md#self-loop-exit-byte-scan),
[Count Self-Loop Exit-Byte Scan](../../REGULATOR_DECISIONS.md#count-self-loop-exit-byte-scan),
[Self-Loop Exit-Byte Skips Outside Counting](../../REGULATOR_DECISIONS.md#self-loop-exit-byte-skips-outside-counting).

#### DFA counting

`Dfa.countMatches` counts in one DFA session, starting each search at the
previous match end, with the forward search's routes plus the count
[self-loop scan](#self-loop-exit-byte-scans). It returns `COUNT_UNSUPPORTED`
for a start-anchored program, a DFA that does not initialize, a start state
that cannot be allocated, a quit, or an empty match, and `COUNT_BAILED` when a
search fails, the cache resets too often, or the count is one of the 16 that
follow two bailed counts in a row ([When the DFA fails](#when-the-dfa-fails)).
Callers: `CP.countDfaMatches`, the inner and window literal count loops, and
the [retained class count DFA](#retained-class-count-dfa).
[Thrashing DFA skipped across calls](OPTIMIZATION_CATALOG.md#thrashing-dfa-skipped-across-calls),
[Count Fallback After Repeated Bails](../../REGULATOR_DECISIONS.md#count-fallback-after-repeated-bails).

#### Many-match DFA

A `MANY_MATCH` DFA reports every pattern ID whose match marker it reaches.
When its program has no empty-width assertions, each state holds its own
matches (`statesHoldOwnMatches`) and the search needs no end-of-text step;
otherwise states keep RE2's one-byte-late matches, which a state reports
only on the byte after the match ends. `Dfa.searchMany` serves `Re2Set`;
`Dfa.searchManyFull` serves the tagged alternation program through
`Dfa.searchManyFullJudgingSlowResets`, which adds its
[slow-reset skip](#when-the-dfa-fails); the reverse program's start-set DFA
serves the match start set. No pointer table or paired rows.
[Many-match states that hold their own matches](OPTIMIZATION_CATALOG.md#many-match-states-that-hold-their-own-matches),
[Many-Match States Hold Their Own Matches](../../REGULATOR_DECISIONS.md#many-match-states-hold-their-own-matches).

#### Candidate start cursor

A matcher route on the forward first-match DFA that scans the start-byte
candidates and confirms each with an anchored DFA check, so a find needs no
reverse pass. A literal cursor is the variant that scans for the
[transparent start literal](#transparent-start-literal), or the folded start
run behind it, in place of the start bytes.

- **Chosen:** by `CP.createCandidateStartCursor` for a group-zero matcher with
  no single-byte table, span search, or class counter; not with a disjoint
  suffix-repeat matcher, compact class counter, scan plan, longest match,
  required prefix, anchor, or nullable program. Other than a literal cursor, it
  also needs a pattern with no fixed length and no empty-width assertion, and a
  first-match DFA with start-byte acceleration, which must have a start literal
  filter when a prefix run starts every match. A matcher also creates it the
  first time a span search hands a find to the program.
- **Bounds:** three times the region length of work per matcher reset and 128
  transitions per check.
- **Falls back:** `CANDIDATE_SEARCH_FALLBACK` disables it until the matcher is
  reset, except a literal cursor's fallback on a window under 64 bytes, which
  leaves it enabled. Only a literal cursor whose DFA can quit, whose matches
  have a finite maximum length, and that has no folded run reports quit
  candidates, the candidates whose checks quit, which are settled on the
  submatch engines; any other quit returns `CANDIDATE_SEARCH_QUIT`, which adds
  to the quit streak.
- **Catalog:** [Group-zero matcher routes](OPTIMIZATION_CATALOG.md#group-zero-matcher-routes).
- **Decision:** [Bounded Candidate-Start Cursor](../../REGULATOR_DECISIONS.md#bounded-candidate-start-cursor).

#### Group-zero forward cursor

The forward first-match DFA kept across a matcher's finds, with its
fixed-distance candidates and byte-scan state; each find is one count-style
forward search for the end (the search `Dfa.countMatches` makes for each
match), and the start comes from the fixed width, an empty match, a single
UTF-8 character's lead byte, a nullable pattern without assertions, or the
reverse DFA (`CP.findGroupZeroBoundary`). Built on first use
(`CP.createGroupZeroForwardCursor`) unless the pattern has a disjoint
suffix-repeat matcher, compact class counter, scan plan, word-run matcher,
longest match, required prefix, anchor, or DFA-unsupported assertion. With a
tagged alternation program, the tagged many-match DFA then picks the capture
branch (`CP.materializeTaggedAlternation`); when it declines, the ordinary
engine resumes at the cursor's match start. A quit adds to the quit streak;
another failure lets the ordinary engine run.
[Match starts without a reverse DFA](OPTIMIZATION_CATALOG.md#match-starts-without-a-reverse-dfa),
[Reusable Group-Zero Forward Cursor](../../REGULATOR_DECISIONS.md#reusable-group-zero-forward-cursor).

#### Reverse program

The forward program reversed, with its assertions swapped, compiled lazily on
the first search that needs a match start (`CP.reverseProg`), in the reverse
share less any inner or window literal search. It compiles from the lowered
program's normalized expression when the pattern has one, otherwise from the
normalized suffix, so a pattern whose lowered program rewrites a terminal
Trino `$`, or Java's `$` or `\Z` under `UNIX_LINES`, has one. There is none
when that program has DFA-unsupported assertions or a directional repetition
(a Java counted repeat of at least two required copies whose body matches
empty only through an assertion), when the stored reverse expression's
retained size exceeds the reverse share at compile time, or when its compile
runs out of memory; searches then run without it. Its longest-match DFA gets
all of its DFA allowance and lends up to half of its free memory to the match
start set's many-match DFA. See [Reverse DFA](REVERSE_DFA.md).
[RE2 optimizations used as ported](OPTIMIZATION_CATALOG.md#re2-optimizations-used-as-ported).

#### Lowered boolean program

A second program in which a terminal final-line `$` (Trino's `$`, Java's `$`
and `\Z` under `UNIX_LINES`) is lowered so the DFA can run it
(`BooleanRegexpLowering.lowerTerminalFinalLineEnds`,
`CP.compileLoweredBooleanProgram`). Kept only without a scan plan and when the
lowered program has no text-dependent assertions or full case folding; the
pattern's own program then has no DFA allowance. Boolean `find`, `lookingAt`,
and the matcher's lowered searches run on it.
[Assertions on the DFA with lazy quit](OPTIMIZATION_CATALOG.md#assertions-on-the-dfa-with-lazy-quit).

#### OnePass

RE2's one-pass engine: one table step per byte, captures from action bits,
anchored searches only.

- **Built:** at compile time for a forward program that is one-pass, whose
  text-dependent assertions it supports (not Java's `(?m)` anchors or Trino's
  line anchors), with fewer than 65,000 nodes whose tables, at RE2's four bytes
  per action, fit a quarter of the DFA allowance; charged from that allowance
  at the eight bytes per action it actually uses, up to half of it. The tables
  of a program that is one-pass only because of a final-line end are released
  and restored if they yield (the final-line OnePass row of
  [Analysis](#analysis-buildwithprogram)).
- **Chosen:** first in `CP.runSubmatchEngine` for an anchored search whose
  capture slots it supports: up to 4 explicit groups in RE2's packed form, up
  to 31 with extended masks. The ordinary engine skips the anchored DFA for it
  on at most 4 KiB when groups beyond group zero are wanted, or at most
  16 bytes otherwise, and `CP.matchAnchoredSubmatch` uses it on at most 4 KiB.
- **Falls back:** BitState.
- **Catalog:** [OnePass next-state offsets](OPTIMIZATION_CATALOG.md#onepass-next-state-offsets),
  [OnePass past RE2's limits](OPTIMIZATION_CATALOG.md#onepass-past-re2s-limits).
- **Decision:** [Extended OnePass Captures](../../REGULATOR_DECISIONS.md#extended-onepass-captures),
  [OnePass Next-State Offsets](../../REGULATOR_DECISIONS.md#onepass-next-state-offsets).

#### BitState

RE2's bounded backtracker with a visited bitmap of one bit per output list of
the program and text position.

- **Available:** `Prog.canBitState`, at most 32,767 output lists.
- **Bounds:** the anchored text limit comes from a 256 KiB bitmap and the
  unanchored one from RE2's 256 Kibit, each lowered at compile time until the
  bitmap, slots, and job stack fit the program's share
  ([Limits and defaults](REGULATOR_API.md#limits-and-defaults)).
- **Chosen:** second in `CP.runSubmatchEngine`, and in place of the anchored
  DFA when groups beyond group zero are wanted and the text fits its anchored
  limit; the [direct capture route](#the-ordinary-engine) on 4 KiB and more;
  the anchored submatch route, where OnePass cannot serve the requested slots;
  and position-automaton windows whose bitmap fits 8 KiB.
- **Falls back:** the position automaton or the Pike NFA.
- **Catalog:** [OnePass, BitState, and NFA](OPTIMIZATION_CATALOG.md#onepass-bitstate-and-nfa),
  [RE2 optimizations used as ported](OPTIMIZATION_CATALOG.md#re2-optimizations-used-as-ported).
- **Decision:** [Bounded Direct BitState Capture](../../REGULATOR_DECISIONS.md#bounded-direct-bitstate-capture).

#### Pike NFA

RE2's NFA simulation (`Nfa`), the last resort, which can always answer.
`Nfa.searchGroupZero` serves group-zero searches; `Nfa.search` serves capture
and boolean searches; and `Nfa.searchTagged` serves the tagged alternation
program. Its capture passes are planned at compile time within the forward
share (`Nfa.planCaptureSearches`): one pass when its slots fit, otherwise
bounded passes, and compilation fails if even four-slot passes do not fit.
[OnePass, BitState, and NFA](OPTIMIZATION_CATALOG.md#onepass-bitstate-and-nfa),
[RE2 optimizations used as ported](OPTIMIZATION_CATALOG.md#re2-optimizations-used-as-ported).

#### Position automaton

A bit-parallel automaton (`PositionNfa`) that finds the earliest end of any
match in a window.

- **Built:** `PositionNfa.build` for an acyclic forward program with
  no assertions, not end-anchored, never empty, with at most 512 positions and
  32 fan-in tests; kept when it yields to the forward DFAs.
- **Chosen:** `CP.searchOnPositionNfa`, third in `CP.runSubmatchEngine` for
  group-zero and boolean searches, and when a boolean search's DFA is skipped
  after slow resets. An unanchored search finds the earliest end, answers a
  boolean search there, and otherwise searches a window of the maximum match
  length around it on BitState or the Pike NFA. An anchored search searches
  the first maximum-length bytes directly, and a full match longer than that
  bound fails without running either.
- **Catalog:** [Bit-parallel position automaton for bounded repeats](OPTIMIZATION_CATALOG.md#bit-parallel-position-automaton-for-bounded-repeats).
- **Decision:** [Bit-Parallel Position Automaton After DFA Failure](../../REGULATOR_DECISIONS.md#bit-parallel-position-automaton-after-dfa-failure).

#### Tagged alternation program

A set program over the branches of a top-level alternation whose branches are
capture groups 1 to n in order, with no nested capture and no line or text
anchor, in a leftmost-first program that is not one-pass
(`TaggedAlternationProgram.compile`). Its many-match DFA picks the winning
branch of a span the group-zero forward cursor found;
`TaggedAlternationProgram.search` runs a tagged Pike NFA in the ordinary
engine's submatch phase for programs with text-dependent assertions. Its
many-match searches skip their DFA after slow resets as [When the DFA
fails](#when-the-dfa-fails) describes, and the ordinary capture engines run.
[Thrashing DFA skipped across calls](OPTIMIZATION_CATALOG.md#thrashing-dfa-skipped-across-calls).

### Start acceleration

Where a route below weighs how rare a byte or literal is, it reads either the
caller's byte frequencies or fixed probabilities in English text, as
[Byte frequencies](REGULATOR_API.md#byte-frequencies) lists per route.

#### Prefix acceleration

Compilation configures the forward program's scan for the literal every match
begins with (`Compiler` through `Prog.configurePrefixAccel`). Per search,
`Prog.prefixAccel` takes the first form in this table whose condition holds,
with `Prog.prefixAccelStrategy` choosing among the case-sensitive pair forms.
The vector pair scans live in `VectorPrefixScanner`.

| Form | Chosen when |
|---|---|
| Folded run behind a lead | `Compiler.foldedRunForAccel` found a folded run of 4 to 9 bytes (3 when a rare ASCII letter leads) behind a lead, the part of the match before the run, whose widths differ by at most 8 bytes. A run replaces a folded prefix only when it is rarer and its lead varies; with no prefix the rarest run is used, earliest on ties, unless every match starts with it and preferred vectors have 64 lanes |
| Folded prefix masks | A `(?i)` prefix with no lead, scanned over its first 9 bytes for its first and last bytes unless another pair is more than four times rarer |
| Single-byte prefix | A one-byte case-sensitive prefix; the DFA fuses the scan into its loop |
| Rare-byte probe | A case-sensitive prefix of at least 2 bytes whose probe `ByteFrequencies.probeOffset` moved from an ASCII first byte to a byte more than four times rarer; checks whichever of the first and last bytes is farther from the probe; the default uniform frequencies never move it |
| Pair vector scan | A case-sensitive prefix of at least 2 bytes, probe at the first byte, Vector API, window of at least 1 KiB; with a prefix literal set, the set's vector scan |
| SWAR pair scan | A case-sensitive prefix of at least 2 bytes, probe at the first byte, a first byte that is not ASCII, and a window under 1 KiB or no Vector API |
| Repeated first byte | A case-sensitive prefix of at least 2 bytes, probe at the first byte, an ASCII first byte, and a window under 1 KiB or no Vector API; checks the last byte per candidate |

- **Prefix literal set:** up to 8 literals that extend a prefix of 2 to 5
  bytes and share one exact byte at a common offset past it, built only with
  the Vector API and a probe at the first byte, charged last in `selectRoutes`
  and kept only if the DFAs keep their minimum.
- **Bounds:** a literal scan whose failed candidates compare more than
  64 bytes beyond its progress continues with Knuth-Morris-Pratt (KMP); the
  shift table is charged to the program and must fit.
- **Callers:** the DFA's start loops; BitState's unanchored search and the
  capture Pike NFA when unanchored with no match and no thread queued
  (`Prog.prefixAccel`); the group-zero NFA and position automaton through
  `Prog.skipToStartCandidate`; and `CP.findExactLiteral`.
- **Catalog:** [Front-and-back prefix scan](OPTIMIZATION_CATALOG.md#front-and-back-prefix-scan),
  [Folded prefix masks](OPTIMIZATION_CATALOG.md#folded-prefix-masks),
  [Rare-byte probe](OPTIMIZATION_CATALOG.md#rare-byte-probe),
  [KMP handoff for dense false candidates](OPTIMIZATION_CATALOG.md#kmp-handoff-for-dense-false-candidates).
- **Decision:** [Folded Prefix Candidate Scan](../../REGULATOR_DECISIONS.md#folded-prefix-candidate-scan),
  [Literal Prefix Vector Scan](../../REGULATOR_DECISIONS.md#literal-prefix-vector-scan),
  [Literal Probe Byte Selection](../../REGULATOR_DECISIONS.md#literal-probe-byte-selection).

#### Transparent start literal

A literal of 2 to 64 bytes that every match consumes right behind a leading
assertion, in an unanchored, non-nullable program with no prefix
acceleration (`Prog.buildTransparentStartLiteral`), admitted when the DFAs keep
their minimum and a search can use it (`CP.searchesTransparentStartLiteral`).
A search uses it in one of two ways. When the DFA runs the assertions, the
[candidate start cursor](#candidate-start-cursor) scans for it, which needs a
pattern that allows that cursor (no longest match, scan plan, disjoint
matcher, anchor, nullable program, or required prefix). When the DFA cannot
run them, the group-zero NFA skips to it, which needs only that the pattern
have no required prefix. A folded start run behind
it feeds the cursor in its place when the DFA runs the assertions and the
run's pair is more than four times rarer (`CP.rarerFoldedStartRun`); the
literal stays configured for every other route.
[Transparent start literal](OPTIMIZATION_CATALOG.md#transparent-start-literal).

#### Start-byte scans

Each forward unanchored DFA instance without a prefix scan builds a start-byte
set of up to 64 bytes (`Prog.buildStartByteCandidates`), scanned as packed
bytes, a range, or nibble tables, after a sample shows candidates are sparse;
the vector scans for start bytes, start literal filters, and class filters
live in `VectorByteSetScanner`. Fixed-distance byte candidates use the byte
set at an offset up to 16 bytes into the match when that set is smaller. A
forward search or count of at least 4 KiB, or the creation of a group-zero
forward cursor, requests them, and they are kept only when the DFA's free
state memory holds them.
[Start-byte and byte-set scans](OPTIMIZATION_CATALOG.md#start-byte-and-byte-set-scans),
[Small Candidate-Byte Vector Scan](../../REGULATOR_DECISIONS.md#small-candidate-byte-vector-scan).

#### Start literal filter

A nibble-table filter for up to 8 groups of leading literals at 3 positions
(`StartLiteralFilter`), built by the DFA when the Vector API is present, the
start set has at most 16 bytes and is not nullable, and the filter's density is
at most a quarter of the start bytes' probability. A rare start set, one
whose probability in English text is under 0.05, admits only a two-literal
filter, and only with 64-lane vectors; that limit does not apply to a rare
set of more than three bytes with no small-set or range scan of its own.
Searches of at least 1 KiB scan it with vectors and shorter ones use the
scalar filter or the start-byte table. The literal alternation trie and the
inner literal search's literal sets use it too.
[Start literal filter](OPTIMIZATION_CATALOG.md#start-literal-filter),
[Start Literal Filter](../../REGULATOR_DECISIONS.md#start-literal-filter).

#### Start class filter

Byte ranges at the first two or three offsets, built by the DFA when there is
no literal filter, the start set has its own vector scan, and its start
probability is at least 0.002 (`Dfa.buildStartClassFilter`). Vector scans from
1 KiB; shorter searches use the start-byte table.
[Start-byte and byte-set scans](OPTIMIZATION_CATALOG.md#start-byte-and-byte-set-scans),
[Start Class Filter](../../REGULATOR_DECISIONS.md#start-class-filter).

### Early rejection

#### Required prefix

A pattern of the form `^literal…` compiles only its suffix; the ordinary
engine requires the prefix at the context start and continues anchored after
it, and the DFA has an integer loop for case-sensitive prefixes of at least
16 bytes. A required prefix excludes the tagged alternation program,
pre-engine matchers, inner and window literal searches, literal neighbors, the
candidate start cursor, transparent start literal, group-zero forward cursor,
matcher class counter, single-byte table, and long-window required literal.
[RE2 optimizations used as ported](OPTIMIZATION_CATALOG.md#re2-optimizations-used-as-ported).

#### Required bytes

A literal, or one of up to three bytes (the one-of bytes), that every match
holds (`RequiredBytes.analyze`). Its final form is charged in `selectRoutes`,
stepping down when it costs a forward DFA its initialization, from the
long-window literal to the short-window reject to none; the table lists those
two forms in the reverse order:

| Form | Checked by | Chosen when |
|---|---|---|
| Short-window reject | `CP.shortWindowLacksRequiredBytes`, in full-`Slice` `find`, unanchored scan-plan `find`, and matcher finds | Required bytes and no single-byte table; windows under 256 bytes, less beside an inner literal search |
| Long-window literal | `CP.longWindowLacksRequiredLiteral` in full-`Slice` `find`, DFA counts, unanchored one-shot calls, and `RM.findGeneral` | `CP.mayCheckRequiredLiteralOnLongWindows` and `CP.checksRequiredLiteralOnLongWindows`: a general pattern with no prefix, anchor, counter, scan plan, or other literal route that would search the same bytes |
| Literal beside a route | the long-window check | The long-window check was refused, and `RequiredBytes.literalBesideRoutes` finds a rarer literal no other route searches |
| Inner-literal handoff | `CP.findFromRequiredLiteral` | `CP.handsOffRequiredLiteral`: the inner literal search runs first, its minimum is at most 256 bytes, and the literal is the inner literal, or the inner literal plus one final byte that its suffix gate admits alone |

[Required-byte and match-length rejects](OPTIMIZATION_CATALOG.md#required-byte-and-match-length-rejects),
[Short-Window Required Bytes Reject](../../REGULATOR_DECISIONS.md#short-window-required-bytes-reject),
[Required Literal Absence On Long Windows](../../REGULATOR_DECISIONS.md#required-literal-absence-on-long-windows).

#### Match-length rejects

Compile-time facts reject input before any engine: shorter than the minimum
match (searches under 4 KiB), longer than the maximum span (patterns anchored
at both ends, and `count`), or, for an anchored search, a first byte no match
starts with.
[Required-byte and match-length rejects](OPTIMIZATION_CATALOG.md#required-byte-and-match-length-rejects).

### Literal searches

#### Exact literal

A pattern that is one unanchored case-sensitive literal takes the
`EXACT_LITERAL` shape: `find` and `count` run the program's
[prefix scan](#prefix-acceleration), and spans (`CP.findExactLiteralSpan`) use
the prefix scan when at least 64 bytes remain or the probe moved, else
`Slice.indexOf`. It is the first span search a group-zero matcher tries.
`ExactLiteralTrinoRegexp` is Trino's form.
[Front-and-back prefix scan](OPTIMIZATION_CATALOG.md#front-and-back-prefix-scan).

#### Literal search kernel

`LiteralSearchKernel`: a call-free 8-byte-word loop that tests a literal's
first and last bytes, with KMP once failed candidates compare more than
64 bytes past its progress. A `CONTAINS` plan of a literal of at least 2 bytes
keeps one (yields, except in Trino and for literals over 64 bytes); `find` uses
it on windows of at least 64 bytes and `Slice.indexOf` below. The dot-star
literal span, ordered literals, literal gaps, literal neighbors, inner and
window literal searches, required bytes, and LIKE's contains matcher also use
it, LIKE at every length.
[Call-free pair word scan](OPTIMIZATION_CATALOG.md#call-free-pair-word-scan).

#### Short literal in two words

`LiteralMatchKernel.matchesShortLiteralAt` compares a literal of 1 to 16 bytes
as a first and last word. Only LIKE's `SHORT_*` strategies and generated LIKE
classes use it; `LiteralMatchKernel`'s other methods are plain `Slice`
comparisons, which the literal plans call.
[Short literal in two words](OPTIMIZATION_CATALOG.md#short-literal-in-two-words),
[Short LIKE Literal Comparisons](../../REGULATOR_DECISIONS.md#short-like-literal-comparisons).

#### Inner literal search

The reverse-inner search (`InnerLiteralSearch`): find a literal inside the
pattern, run a reverse longest-match DFA of the prefix anchored at each hit,
and confirm forward.

- **Chosen:** in [Analysis](#analysis-buildwithprogram), after the routes it
  excludes, when `InnerLiteralSearch.analyze` accepts an unanchored program
  with no prefix acceleration whose assertions the DFA runs. Literal kinds: a
  single exact ASCII literal of up to 64 bytes, which must be neither a
  letter, digit, nor whitespace when it is one byte long; a set of 2 to 8
  ASCII literals of 3 to 64 bytes each that a
  [start literal filter](#start-literal-filter) can search; a pair of rare
  adjacent ASCII classes; or an ASCII case-folded literal.
- **Bounds:** memory from the reverse share, at most half for the prefix
  program, whose DFA must initialize. A minimum window per kind
  (`InnerLiteralSearch.minimumSearchBytes`): 96 bytes for a single or folded
  literal, 64 for one byte or a class pair, 256 for a literal set (1,024 behind
  a class run), 1,024 for a folded literal with no searched head. Beside a
  short fixed-width matcher every minimum is 64 bytes, and a literal-set count
  not behind a class run starts at 64 bytes.
- **Falls back:** `FALLBACK` to the DFA when the first hit is within 64 bytes
  of the start, a candidate overlaps confirmed text (with byte gates, only
  hits that pass them count for these two), the reverse search would read back
  past the previous candidate's end, a DFA fails, or at least 64 hits rejected
  by the byte gates average fewer than 8 bytes apart.
- **Callers:** the ordinary engine, full-`Slice` `find` (first for a gated
  one-byte literal), counts, and the required-literal handoff.
- **Catalog:** [Reverse-inner literal search](OPTIMIZATION_CATALOG.md#reverse-inner-literal-search),
  [Inner literal byte gates](OPTIMIZATION_CATALOG.md#inner-literal-byte-gates).
- **Decision:** [Minimum Inner Literal Search Window](../../REGULATOR_DECISIONS.md#minimum-inner-literal-search-window),
  [Inner Literal Class Pairs](../../REGULATOR_DECISIONS.md#inner-literal-class-pairs),
  [Inner Literal Byte Gates](../../REGULATOR_DECISIONS.md#inner-literal-byte-gates).

#### Window literal search

An exact ASCII literal of 3 to 64 bytes within 255 bytes of every match start;
each occurrence tries anchored forward DFAs from the starts in its window
(`WindowLiteralSearch`). Chosen only without an inner literal search or
transparent start literal, and not where the first-match DFA would scan a one-
or two-literal start filter with 64-lane vectors. Runs on windows of at least
96 bytes; falls back when the first window is within 64 bytes of the start, a
DFA fails, or its tries cost more than half the distance from the search start
to the current literal occurrence, plus 64, where a try costs the bytes it
reads plus 16.
[Window literal search](OPTIMIZATION_CATALOG.md#window-literal-search),
[Window Literal Search](../../REGULATOR_DECISIONS.md#window-literal-search).

### Specialized matchers

Each answers what the ordinary engine would and declines to it otherwise. The
Rule column of [Analysis](#analysis-buildwithprogram) gives each one's budget
rule; an entry with no Analysis row states its own charge.

#### Dot-star literal span

An unanchored `.*lit.*`: one non-empty case-sensitive literal between two
greedy dot gaps with the same stops (a line feed or other stops; not dot-all),
no captures, and a literal that holds no stop and that the dots read as whole
characters (`DotStarLiteralSpanMatcher.analyze`). It finds the literal, then
widens over the dots. Dots with other stops, such as Java's default dot and
Rust's CRLF dot, take `DotStarLiteralSpanMatcher.MultipleStops` (at most 8
stops, at most 3 of them ASCII). Serves counts, group-zero matcher finds, and
unanchored one-shot calls; anchored calls keep the ordinary engine. Trino's
form is `DotStarLiteralTrinoRegexp`.
[Dot-star literal span](OPTIMIZATION_CATALOG.md#dot-star-literal-span).

#### Ordered literals

Two or more literals found in turn (`OrderedLiteralMatcher`). RE2, Java, and
Rust use it for boolean `find` when every gap matches any byte sequence, as in
RE2 Latin-1 or Rust bytes mode; Trino for `contains` with dot-all gaps, falling
back to the ordinary engine when a gap is not whole characters; LIKE for
literals separated by `%`.
[Ordered literals](OPTIMIZATION_CATALOG.md#ordered-literals).

#### Literal neighbors

`C+ L D+`, a literal between two class runs, answered for boolean `find` by
scanning the literal and reading one byte on each side
(`LiteralNeighborMatcher`). Undecided, as on dense one-byte literals, it
defers to `CP.findOnEngine`.
[Literal neighbors](OPTIMIZATION_CATALOG.md#literal-neighbors).

#### Literal alternation

A trie for 2 to 64 capture-free exact literals of up to 64 bytes
(`LiteralAlternationSpanMatcher`), with a root table and, from 64 bytes with
the Vector API, a start literal filter. An alternation of ASCII case-folded
literals has no trie: it uses a separate masked matcher, which needs the
Vector API (`LiteralAlternationSpanMatcher.analyzeFolded`). It returns
`DECLINED` when the filter's stops are dense from the input start, and the
ordinary engine runs. A matcher with at least
64 bytes left hands off to the program: the candidate cursor where the
literals differ in length, the group-zero forward cursor where they share one.
Trino takes it as `LiteralAlternationTrinoRegexp` with no program, and Trino
`(?i)` alternations with full case folding as
`FullCaseFoldAlternationTrinoRegexp`.
[Literal alternation trie](OPTIMIZATION_CATALOG.md#literal-alternation-trie).

#### Literal set

An Aho-Corasick automaton for more than 64 capture-free literals
(`LiteralSetSpanMatcher`), with dense rows near the root, a root byte-set skip
with the Vector API, and a skip table for literals of at least 4 bytes, each
kept only where it does not cost a forward DFA its initialization. It answers
`find` when the forward longest-match DFA cannot initialize, and `count` when
it has its skip table or the forward first-match DFA cannot initialize; the
engine answers the rest. Without a program it answers everything. Trino takes
it as `LiteralSetTrinoRegexp` with no program.
[Aho-Corasick for large literal sets](OPTIMIZATION_CATALOG.md#aho-corasick-for-large-literal-sets),
[Skip ahead in sets of long literals](OPTIMIZATION_CATALOG.md#skip-ahead-in-sets-of-long-literals),
[Large Literal Alternations](../../REGULATOR_DECISIONS.md#large-literal-alternations).

#### Fixed-width byte span

Matches of one fixed character count, up to 256 positions: scan one candidate
position, verify the rest (`FixedWidthByteSpanMatcher`). Candidates are an
ASCII byte, a rare position, or, with the Vector API, a block of classes
(`VectorBlockMaskScanner`). A matcher whose candidate byte set includes a
non-ASCII byte, set at construction, returns `BAILED` after at least 64 failed
candidates at more than one per 32 bytes, and the ordinary engine continues;
a block search never bails. Only a rare-candidate or block search steps aside
for the engine's scans (`CP.yieldsToEngineRoute`); an ASCII singleton scan
never does. It steps aside where the program skips to start candidates on its
own, a matcher that bails on dense candidates qualifies for the matcher class
counter, or the first-match DFA gives a one-bit start literal filter. Trino's
forms are `FixedWidthByteTrinoRegexp` and a `FIXED_WIDTH` pattern with no
program.
[Fixed-width byte span](OPTIMIZATION_CATALOG.md#fixed-width-byte-span),
[Fixed-width rare class scan](OPTIMIZATION_CATALOG.md#fixed-width-rare-class-scan),
[Fixed-width block search](OPTIMIZATION_CATALOG.md#fixed-width-block-search),
[Fixed-Width Rare Class Candidates](../../REGULATOR_DECISIONS.md#fixed-width-rare-class-candidates).

#### Short fixed-width matcher

A fixed-width matcher kept beside an inner literal of 2 or more bytes, where
the shape stays `ENGINE`. Counts and matcher finds run it on windows below the
inner literal search's minimum.
[Fixed-width byte span](OPTIMIZATION_CATALOG.md#fixed-width-byte-span).

#### Disjoint suffix-repeat matcher

A capture-free `A B{n} x`: `A` an ASCII class; `B` a class with at most
64 ranges that excludes `x`; `n` the exact repeat count, 1 to 1,000; `x` one
ASCII character; nothing case-folded. Find `x` and validate backward
(`DisjointSuffixRepeatMatcher`). It runs first in the ordinary engine and
answers `count` on `ENGINE` patterns.
[Fixed-width byte span](OPTIMIZATION_CATALOG.md#fixed-width-byte-span).

#### Single-byte table and byte run

A 256-entry table for a pattern whose every match is one byte
(`SingleByteMatcher`), and a byte run for runs of one-byte members
(`SingleByteMatcher.analyzeRun`). They give the `BYTE_TABLE` shape, which
answers `find` on input of at most 64 bytes and leaves longer input to the
DFA's byte scans. Its `count` uses the table on input of at most 64 bytes
when there is no byte run; otherwise it uses the class counter when there is
one, else the DFA. A group-zero matcher uses the table with fewer than
64 bytes left. Trino's `count` uses the table at any length.

#### Single-byte repeat matcher

Trino only: a greedy unbounded `x*` of a non-empty one-byte member set under
optional captures, with no required prefix or text-dependent assertions
(`SingleByteRepeatMatcher`), built on first use and not charged to the budget.
Trino's `count`, `position`, `extractAll`, `split`, and replacements iterate on
it.

#### Class-run counter

One pass over runs of a character class, cut by the repeat bounds
(`BoundedCharacterClassCounter`).

- **Compact route:** a large Unicode class repeat, or a class-run alternation
  with captures (`ClassRunAlternationCaptures`, which writes the groups from
  the run length), compiles with no real program, unless it keeps a
  [retained count DFA](#retained-class-count-dfa), and takes `CLASS_RUN`.
- **Matcher route:** a single large Unicode class or a greedy class repeat
  with no captures; serves group-zero matcher finds and counts.
- **Count route:** built on first use from the class repeat when neither is
  held; counts runs from their starts for an unbounded byte-class repeat, and
  hands long runs to a vector scan.
- **Catalog:** [Class-run counter](OPTIMIZATION_CATALOG.md#class-run-counter),
  [Class-run alternation captures](OPTIMIZATION_CATALOG.md#class-run-alternation-captures).
- **Decision:** [Bounded Character-Class Counting](../../REGULATOR_DECISIONS.md#bounded-character-class-counting).

#### Retained class count DFA

A DFA count program kept beside the compact class counter when the class
repeat's expansion is small enough (`RetainedCharacterClassCountDfa.supports`)
and its DFA allowance is at least 128 KiB. It counts input of at least 1 MiB
whose sample is not dense, and the counter takes the rest and any bail.
[Class-run counter](OPTIMIZATION_CATALOG.md#class-run-counter).

#### Word-run matcher

`\b class+ \b`, or greedy `\b class{m,n} \b` with `m` at least 1, over ASCII
word runs (`WordRunMatcher`), run first in the ordinary engine.
[Word-run plan](OPTIMIZATION_CATALOG.md#word-run-plan),
[Word-Run Plan](../../REGULATOR_DECISIONS.md#word-run-plan).

#### Whole-input capture plan

Capture endpoints of one anchored greedy run over every character or byte
(`WholeInputCapturePlan`), answered in the ordinary engine when the search
covers the whole context.

### Scan plans

A short bounded program of literal, run, optional, and capture operations for
a common shape (`ScanPlan.analyze`), interpreted by six executors: end-anchored,
partial, and unanchored search, each with an ASCII case-folded twin. Runs live
in `ScanPlanRun`, which reads sets of some but not all non-ASCII characters
through `Utf8MemberTable`.

- **Chosen:** in [Analysis](#analysis-buildwithprogram) (the scan plan rows),
  for a leftmost-first pattern that cannot match empty, starting anchored, with
  a literal, or with a class run; an unanchored plan also needs a capture, a
  variable-length run, and a continuation its search can find. At most 32
  operations, 4 optional parts, 16 groups, and 256 bytes per literal operation,
  counting an expanded fixed literal repeat. A plan refuses Latin-1 nodes, lazy
  repeats, and an unbounded-run start with a final-line end, so RE2 Latin-1
  patterns get none; eligible Rust bytes-mode patterns keep theirs. A plan
  gives the `SCAN_PLAN` shape.
- **Bounds:** an unanchored search hands off once failed attempts examine more
  than 2,048 bytes plus four times the distance covered; a boolean search also
  hands off after dense failed attempts.
- **Falls back:** the ordinary engine from the handoff offset; a ranged call
  whose region ends before the input end runs the ordinary engine.
- **Characters:** plans read non-ASCII bytes as the ordinary engine does, in
  every language.
- **Catalog:** [Bounded scan plan](OPTIMIZATION_CATALOG.md#bounded-scan-plan),
  [Boolean-call shortcuts](OPTIMIZATION_CATALOG.md#boolean-call-shortcuts),
  [RE2-rule runs](OPTIMIZATION_CATALOG.md#re2-rule-runs),
  [Validating run skip](OPTIMIZATION_CATALOG.md#validating-run-skip); the
  [scan plan reference](../benchmarks/SCAN_PLAN.md) has the full design.
- **Decision:** [RE2 Scan Plans](../../REGULATOR_DECISIONS.md#re2-scan-plans),
  [Trino Specialized Byte Scans](../../REGULATOR_DECISIONS.md#trino-specialized-byte-scans).

### Generated classes

With `setGenerateBytecode(true)`:

- **RE2, Java, Rust:** a `SCAN_PLAN` pattern whose plan is case-sensitive
  (`CP.generateScanPattern`) becomes a hidden subclass of its scan-plan class
  (`ScanKernelGenerator.generateCompiledScanPattern`) that emits
  `matchInternal`, and `find`, `count`, `matches`, and `lookingAt` where they
  reach the plan. Its helpers live in `ScanKernelSupport`, with vector loops
  in `VectorScanKernelSupport`.
- **Trino:** only when no specialized `TrinoRegexp` class was chosen and
  `ScanKernelGenerator.TrinoRoutes.of` accepts: a case-sensitive plan, a pattern
  that cannot match empty, and a count that runs on the plan. The class emits
  each operation that reaches the plan; `contains` answered by a retained
  literal kernel is inherited, not emitted.
- **LIKE:** every strategy (`TrinoLikeKernelGenerator.generate`), unless a
  method would exceed 8,000 bytes of bytecode; its helpers, KMP fallback
  included, live in `TrinoLikeKernelSupport`.
- **Failure:** any failure to generate or define the class leaves the
  interpreted pattern; `usesGeneratedBytecode()` reports which one runs.
- **Catalog:** [Generated class is the pattern](OPTIMIZATION_CATALOG.md#generated-class-is-the-pattern),
  [Straight-line attempt code](OPTIMIZATION_CATALOG.md#straight-line-attempt-code),
  [Sealed language classes and shapes](OPTIMIZATION_CATALOG.md#sealed-language-classes-and-shapes).
- **Decision:** [Generated RE2 Scan Kernels](../../REGULATOR_DECISIONS.md#generated-re2-scan-kernels),
  [Generated Trino Scan Kernels](../../REGULATOR_DECISIONS.md#generated-trino-scan-kernels),
  [Generated Trino LIKE Kernels](../../REGULATOR_DECISIONS.md#generated-trino-like-kernels).

### LIKE matchers

- `ContainsMatcher`: one literal in the middle, on the literal search kernel
  for more than one byte and `Slice.indexOf` for one.
- `OrderedLiteralMatcher`: two or more literals, each at its first occurrence
  after the previous one.
- `LiteralGapMatcher`: a middle of two or more literals separated only by
  `_` runs, with a `%` before and after it, whose first literal is at least
  2 bytes; it steps over each gap by characters. `%a_b%`, whose first literal
  is one byte, takes the wildcard matcher.
- `TrinoLikeWildcardMatcher`: every other middle with a `_`, as a set of states
  over code points in a per-thread workspace, with a direct path for a middle
  that is one exact `_` run.
