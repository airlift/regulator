# Optimization catalog

This catalog lists the performance optimizations in Regulator's engines and
compilers and credits where each came from. Optimizations preserve each
language's matching contract; Trino regular-expression routes promise agreement
only on valid UTF-8. Regulator is pure Java, with no JNI library or bundled
native code; the only native memory it allocates is an optional DFA table, as
[Runtime acceleration](../../README.md#runtime-acceleration) describes. The
[RE2 optimization registry](OPTIMIZATION_REGISTRY.md) gives the exact triggers
of the RE2 mechanisms cited here by ID. The Origin column reads:

- **RE2**: ported from C++ RE2; an ID links to its registry entry.
- **Rust regex**: from regex-automata or regex-syntax in rust-lang/regex.
- **aho-corasick**, **memchr**: from the Rust crates of those names.
- **Trino**: from Trino's own implementation.
- **ClickHouse**: only as "coverage modeled on" its regex patterns.
- **Regulator**: designed here.
- **Unknown**: the public history records no source.
- **similar to X** after any source: resembles X, linked to compare.
- **base** after any source: the RE2 mechanism it changes.

## Engine selection and early rejection

Compile-time facts route each search to the cheapest engine that gives the same
answer, or reject the input before any engine runs.

| Optimization | What it does | Applies when | Where | Origin |
|---|---|---|---|---|
| Minimum-length reject | A window shorter than the pattern's minimum match length fails before any engine setup. The engine checks windows under 4 KiB; longer ones skip the check, which saves no work there. A matcher checks again before its general find. | The engine check on windows under 4 KiB, where longer ones skip the metadata load; the matcher check on finds that take the general route rather than a scan plan, span search, or anchored capture route | `CompiledPattern.matchOnOrdinaryEngine`, `RegexpMatcher.findGeneral` | Unknown; the matcher check is Regulator ([#138]) |
| Impossible first byte | Compilation records which bytes can begin a match of a start-anchored program. An anchored search rejects any other first byte with one table load, before OnePass or BitState setup. | Start-anchored, non-nullable programs with no assertion before the first byte | `Prog.computeByteMap`, `CompiledPattern.matchAnchoredSubmatch` | Regulator ([#138]) |
| Short-window required bytes | A pattern may record bytes every match holds: an ASCII literal of two or more bytes, or up to three ASCII bytes of which every match holds one. A window that lacks it returns no match before any engine runs. The test reads 8-byte words and loads the last byte's word only when the first byte is rare. | Windows under 256 bytes, all languages; the fact is dropped when its memory would keep a forward DFA from initializing | `RequiredBytes.analyze`, `RequiredBytes.containsLiteral`, `RequiredBytes.containsOneOf`, `CompiledPattern.shortWindowLacksRequiredBytes` | Regulator ([#147], [design][d-required-bytes]), similar to Rust regex prefiltering ([strategy.rs][ra-strategy]) |
| Anchored find straight to its engine | A matcher's first find on a start-anchored pattern with captures checks the length and first byte, then calls OnePass or BitState directly when the input fits that engine's text limit. It skips the general find, region setup, and the ordinary-engine prologue. | Start-anchored OnePass or BitState patterns with a positive minimum length and no scan plan, required prefix, or literal set | `CompiledPattern.takesAnchoredSubmatchRoute`, `RegexpMatcher.findAnchoredSubmatch` | Regulator ([#138]) |
| Direct BitState capture | When a matcher asks for groups, one bounded BitState pass replaces the forward DFA, the reverse DFA, and the capture pass. | Unanchored leftmost-first matcher searches with groups, not one-pass, from 4 KiB up to the program's BitState text limit | `CompiledPattern.canUseDirectBitStateCapture` | Regulator ([design][d-direct-bitstate]) |
| Match starts without a reverse DFA | When every match has the same byte length, the start is the end minus that length. A nullable pattern with no assertion starts where the search started, and a one-character match that ends in a valid UTF-8 character starts at that character's lead byte. | Fixed-length patterns; patterns such as `.*`; one-character patterns such as `\pL` in UTF-8 | `CompiledPattern.findGroupZeroBoundary`, `Utf8.previousRuneStart` | Regulator ([#77], [design][d-forward-cursor]) |
| Literal boolean plans | When analysis proves a pattern is one literal with optional unrestricted gaps, full-input `find`, `lookingAt`, and `matches` use literal contains, equality, prefix, and suffix tests, including final-line forms. | Patterns that normalize to one literal sequence | `CompiledPattern.selectBooleanPlans`, `ExpressionAnalysis.buildLiteralSequence` | Regulator ([design][d-boolean]) |
| Lowered final-line `$` | A second program rewrites a terminal final-line `$` as an optional LF and end of text, so boolean calls and group-zero bounds run on the DFA instead of the program with the text-dependent assertion. | Trino final-line `$`, and Java `$` under `UNIX_LINES` (`(?d)`); group-zero bounds only when the expression is nonempty and cannot consume LF | `BooleanRegexpLowering.lowerTerminalFinalLineEnds`, `CompiledPattern.compileLoweredBooleanProgram` | Regulator ([design][d-trino-assertions]) |
| Tagged alternation program | For `(a)\|(b)\|…`, where each branch is one capture around a capture-free body, the branches compile without captures into one program whose matches name their branch, as RE2::Set does. A many-match DFA pass over group zero's span, or a tagged NFA, finds the winning branch, and its group is set to group zero's span. | Leftmost-first programs over 512 instructions that are not one-pass, with one group per branch | `TaggedAlternationProgram.compile`, `TaggedAlternationProgram.materialize` | Unknown |
| Match-every-byte full match | A full match of a pattern that accepts every byte string returns at once. | `\C*` in UTF-8 or dot-all `.*` in Latin-1, with at most one group | `Compiler.matchesAnyByteString`, `CompiledPattern.matchOnOrdinaryEngine` | Regulator ([design][d-match-every-byte]); registry entry [O-RE2-016] marks it as having no C++ counterpart |

## Literal and prefix search

Many patterns begin with or contain a literal. These scans find its candidates,
so the automata run only where a match can be.

| Optimization | What it does | Applies when | Where | Origin |
|---|---|---|---|---|
| Front-and-back prefix scan | A candidate must hold the prefix's first and last bytes before the whole prefix is compared. RE2 tests them 32 bytes at a time with AVX2; Regulator tests them with the Vector API on long windows, with 8-byte SWAR words (SIMD within a register) for non-ASCII-led prefixes, and otherwise scans for the probe byte and checks the other byte per candidate. | Case-sensitive prefixes of two or more bytes in unanchored searches, all four regex languages | `Prog.prefixAccel`, `Prog.prefixAccelNoFoldCaseFrontAndBackSwar` | RE2 [O-PROG-007]; the Vector API and SWAR forms are Unknown |
| Fused vector pair scan | The vector loop only tests whether any lane holds both bytes, so HotSpot's C2 JIT compiler compiles it as a counted loop. Candidates are rebuilt and verified after the loop exits, and the scan runs out of line. | Windows of at least 1 KiB with the Vector API and a case-sensitive prefix probed at byte 0; otherwise SWAR or the first-byte scan | `Prog.prefixAccelStrategy`, `VectorPrefixScanner.find`, `VectorPrefixScanner.pairDifference` | Regulator ([#87], [#140], [design][d-prefix-vector]) for the counted loop and deferred verification, similar to memchr ([packedpair][memchr-packedpair]); base RE2 [O-PROG-007] |
| Continuation-byte pair | For a literal that starts with a multibyte UTF-8 character, the pair scan probes that character's last byte instead of its lead byte, which a whole script shares. | UTF-8 literals whose non-ASCII first character ends before the literal's last byte | `Prog.pairOffset` | Regulator ([#141]) |
| Folded prefix masks | A case-insensitive prefix keeps RE2's 9-byte cap, but is scanned with first- and last-byte masks a SWAR word or vector at a time: the vector form ORs 0x20 into letter bytes, and the SWAR form matches both case broadcasts. RE2 scans it with a ShiftDFA. | `(?i)` ASCII prefixes; the vector form from 1 KiB | `Prog.prefixAccelFoldCaseFrontAndBack`, `Prog.foldCaseMatches`, `VectorPrefixScanner.findFoldCase` | Regulator ([#85], [design][d-folded-prefix]); base RE2 [O-PROG-006] |
| Rare-byte probe | The probe moves off byte 0 only to the literal's rarest later byte, and only when that byte's probability under the configured byte distribution, which defaults to uniform, is less than a quarter of byte 0's. Presets measured on English text and JSON, or caller counts, set the distribution. | Case-sensitive multi-byte prefixes with an ASCII first byte, and multi-byte scan-plan leading literals, opt-in through `Options.setByteFrequencies`; the start literal filter and required bytes always use English | `ByteFrequencies.probeOffset`, `ByteFrequencies.englishText`, `ByteFrequencies.fromCounts`, `Prog.prefixAccelProbe` | Regulator ([#13]), similar to memchr ([rare-byte rank][memchr-rank]) |
| KMP handoff for dense false candidates | Failed candidates may compare at most 64 bytes more than the search has advanced. The running total is kept as one position, so the check is a single compare. Past that allowance, the scan continues with KMP, so search time stays linear. | The contains search, and case-sensitive prefix scans of two or more bytes; scan-plan leading literals keep their own scan | `LiteralSearchKernel.chargeFailedCandidate`, `LiteralSearchKernel.findKmp`, `Prog.finishWithKmp` | Regulator ([#18], [#99]) |
| Shared border-free shift table | A literal under 64 bytes whose first byte does not recur has known KMP shifts, so all such literals share one read-only table. Other literals build a table charged to the DFA budget. | Literals using the KMP handoff | `LiteralSearchKernel.computePrefixShifts`, `Prog.configurePrefixAccelBytes` | Regulator ([#81]) |
| Contains search in every language | A search for a literal of two or more bytes anywhere in the input uses the word-at-a-time scan that tests the literal's first and last bytes without calls, with its KMP handoff, instead of `Slice.indexOf`, whose repeated failed comparisons can cost the input length times the literal length. One entry routes start and inner literals to the right kernel. | Literals that fit the forward-DFA allowance, all languages | `Prog.findLiteral`, `LiteralSearchKernel.findContains` | Regulator ([#118]) |
| Substring search on short rows | A Trino exact-literal span with fewer than 64 bytes left uses `Slice.indexOf` instead of the prefix scan, unless the probe byte moved. | Trino regexp exact-literal spans | `CompiledPattern.findExactLiteralSpan`, `CompiledPattern.exactLiteralSpanUsesPrefixScan`, `LiteralMatchKernel.find` | Regulator ([#14]) |
| Transparent start literal | When a pattern begins with line or word assertions and then a literal, the scan finds the literal and the engine checks the assertion from the byte before each hit. The NFA skips to the literal when no thread is live, and a DFA cursor scans for it. | Shapes such as `(?m)^lit` and `\blit`, literals of 2 to 64 bytes | `Prog.buildTransparentStartLiteral`, `Prog.skipToStartCandidate`, `Dfa.createLiteralCandidateStartCursor` | Regulator ([#96]), similar to Rust regex ([literal.rs][rs-literal]) |
| Reverse-inner literal search | For a required literal in the top-level sequence, the search finds the literal, runs the prefix backward to the leftmost start, and confirms forward. It is used only when the prefix cannot hold an earlier match. Quadratic guards, and a first hit within 64 bytes of the start, hand back to the ordinary engine. | Find and count in all four regex languages | `InnerLiteralSearch.analyze`, `InnerLiteralSearch.search`, `InnerLiteralSearch.hasNoEarlierMatch`, `Dfa.searchAnchoredWithStop` | Rust regex ([reverse_inner.rs][ra-reverse-inner], [strategy.rs][ra-strategy]; [#90]) |
| Inner literal forms | A required piece that is one of up to 8 literals of 3 to 64 bytes is searched with the start literal filter, and a literal with case-insensitive ASCII letters after exact bytes, such as `# (?i:noqa)`, is found by its exact leading bytes, with the rest checked by an OR mask. Long searches for one exact literal use the vector byte-set scan for one byte and the vector pair scan otherwise; a one-byte literal that is a letter, digit, or space is not used. | Inner literal searches; the vector form from 1 KiB with the Vector API | `InnerLiteralSearch.findLiteralSetMember`, `InnerLiteralSearch.findFoldedLiteral`, `InnerLiteralSearch.usesVectorSearch` | Regulator ([#103], [#138], [#143]) |
| Short-window inner literal check | A window too short for the reverse-inner search is still checked for the literal, so a short line without it has no match and runs no DFA. | Windows under 64 bytes | `InnerLiteralSearch.search` | Regulator ([#103], [design][d-short-inner]) |

## Start-byte and multi-literal filters

A pattern without one leading literal often still admits only some first bytes.
These filters skip to the next byte, or byte sequence, that can begin a match.

| Optimization | What it does | Applies when | Where | Origin |
|---|---|---|---|---|
| Start-byte scan | The DFA scans to the next byte that can leave its unanchored start state, runs from there, and resumes the scan when it returns to the start state. The byte set is built on first use. | Unanchored forward searches whose start set is selective | `Prog.buildStartByteCandidates`, `Dfa.canUseStartByteAcceleration`, `Dfa.buildStartByteScanSet`, `Dfa.searchForwardScanAcceleration` | Unknown |
| Small byte-set vector scan | Up to three start bytes are packed into one int and scanned with one to three compares per vector. | DFA start and fixed-distance sets of up to three bytes, Vector API, at least 1 KiB | `VectorByteSetScanner.find`, `VectorByteSetScanner.findThree` | Regulator ([design][d-small-byte-set]) |
| Range and nibble-table scans | A start set that is one contiguous range of 4 to 64 bytes is scanned with an unsigned pair of compares. Other sets of 4 to 64 bytes with at most 8 distinct high nibbles are found with two 16-entry nibble lookups and an AND. | DFA start sets; the nibble form also serves the Aho-Corasick root skip and the class counter | `VectorByteSetScanner.findRange`, `VectorByteSetScanner.buildNibbleTables`, `VectorByteSetScanner.findNibbleTable`, `Dfa.findByteSet` | Unknown |
| Scan productivity sampling | Before a scan, the DFA samples four 16-byte windows spread over the input. Dense samples skip a start-byte or fixed-distance scan, and demote a vector set scan to a scalar membership scan. | Start-byte and fixed-distance scans from 64 KiB; vector set scans from 4 KiB, where sets of up to three bytes are sampled only on vectors wider than 128 bits | `Dfa.isByteCandidateScanProductive`, `VectorByteSetScanner.shouldSampleCandidateDensity` | Unknown; the wide-species sample is Regulator ([design][d-small-byte-set]) |
| Short-scan rule | After four scans in a row that each skip fewer than 16 bytes, the loop stops scanning and steps byte by byte. | DFA self-loop scans and the Aho-Corasick root skip | `VectorByteSetScanner.shortScanCount` | Regulator ([#9], [#120]) |
| Fixed-distance byte candidates | When every match has one of a small, selective byte set at a fixed offset of up to 16 from its start, the scan searches for that set and steps back. | Unanchored forward DFA searches of at least 4 KiB | `Prog.buildFixedDistanceByteCandidates`, `Dfa.canUseFixedDistanceByteAcceleration` | Unknown |
| Start literal filter | For at most eight groups of leading literals of three or more bytes, the filter tests three positions per group at once and stops only where all three fit some group, a superset of the literals' starts; the DFA decides each stop. Literals that differ in one bit at a position, such as ASCII or Cyrillic case pairs, share a group through an OR mask. | Vector API; in the DFA, vector scanning from 1 KiB and scalar filtering on shorter windows, except filters selected only for vector scans; the literal alternation matcher from 64 bytes | `Prog.buildStartPositionByteSets`, `StartLiteralFilter.build`, `StartLiteralFilter.canMerge`, `StartLiteralFilter.find` | Regulator ([#89], [design][d-start-filter]), similar to Teddy in aho-corasick ([teddy][ac-teddy-readme]), which credits Hyperscan |
| Filter positions and adoption | The filter takes the three positions with the lowest estimated stop density, from English frequencies and fixed UTF-8 weights. The DFA adopts it only when that density is at least 4 times below the start-byte scan's and the start set has at most 16 bytes; a rare start set also needs more than three start bytes that are not one range, or exactly two literals and 64-byte vectors. | DFA start states | `StartLiteralFilter.build`, `Dfa.buildStartLiteralFilter`, `VectorByteSetScanner.shouldFilterRareStartsWithTwoLiterals` | Regulator ([#89], [#110], [#142]) |
| Two-group filter kernel | With two groups, each position is compared against both groups and the results are ANDed across positions. | Two-group filters | `VectorByteSetScanner.findTwoLiterals` | Regulator ([#89]) |
| Nibble-group filter kernel | With 4 or 8 groups, two nibble lookups give every group's bit at once. Each step loads one vector at the third position and shifts in the first two positions' bits from the previous step. | 4- and 8-group filters, 16 to 64 lanes | `VectorByteSetScanner.findLiteralNibbles`, `StartLiteralFilter.buildNibbleTables` | aho-corasick ([teddy/generic.rs][ac-teddy]) for the one-load shift-in; nibble groups Regulator ([#98], [#142]), similar to Teddy ([teddy][ac-teddy-readme]) |

## Vector and word-at-a-time kernels

The scans above share a few kernels. Vector forms need the incubating Vector
API, and each has a SWAR or scalar form for JVMs without it.

| Optimization | What it does | Applies when | Where | Origin |
|---|---|---|---|---|
| Vector width gate | Vector scans run only when `jdk.incubator.vector` is present and the preferred species holds 16 to 64 byte lanes. Narrower vectors would wrap the 16-entry nibble tables, and wider ones overflow the 64-bit masks. | All vector scans | `VectorSupport.AVAILABLE`, `VectorSupport.PreferredSpecies.hasSupportedLength` | Regulator ([#95], [#104]) |
| 128-bit run and literal scans | Run stops, required-literal checks, and folded-byte scans use a fixed 128-bit species. Byte-set, prefix, and filter scans use the preferred species. | All platforms; on wider hardware the byte-set, prefix, and filter scans widen and these stay at 128 bits | `VectorScanner.findRunStop`, `VectorScanner.containsLiteral` | Unknown |
| SVE candidate masks | Each candidate byte is XORed with its probe, the differences are joined with OR (all must match) or a lane-wise unsigned minimum (any may match), and the result is compared with zero once. This replaces a compare per probe. | aarch64 with 128-bit SVE; NEON and x86 compare each probe and combine with AND or OR | `VectorSupport.sve128`, `VectorPrefixScanner.sveMatches`, `VectorScanner.findRunStopSve`, `VectorByteSetScanner.findTwoSve`, `VectorByteSetScanner.findTwoLiteralsSve` | Regulator ([#132], [#135], [design][d-sve]) |
| Nibble shift on shorts | On x86, the high nibble comes from a 16-bit lane shift and a mask instead of a byte shift. | x86 only; aarch64 keeps the byte shift | `VectorSupport.SHIFT_NIBBLES_AS_SHORTS` | Regulator ([#142]) |
| Needles broadcast once | Run-stop needles are broadcast once before the block loop and reused in each iteration. | Vector run-stop scans | `VectorScanner.findRunStop` | Regulator ([#43]) |
| RE2 run stop in one compare | Run-stop needles are ASCII, so the scan XORs the block with the needle and does one signed compare below 1, which finds needle bytes and every non-ASCII byte together. Several needles combine by lane-wise unsigned minimum. | Non-ASCII runs in RE2, Java, and Rust plans | `VectorScanner.findRe2RunStop`, `VectorScanner.findRe2SetStop` | Regulator ([#43], [#134]) |
| SWAR byte scan | The byte is broadcast into a word, XORed with the input, and found with the zero-byte test, two 8-byte words per step. | Trino literal search; one-byte prefixes in the other languages | `LiteralSearchKernel.findSingleByte`, `Prog.indexOfSWAR` | Unknown |
| Overlapping last word | One-byte scans of 8 bytes or more, and contains scans of at least 8 candidate starts, end with a word that ends at the range end and overlaps bytes already searched, instead of a byte loop. Generated LIKE emits the same ending. | One-byte and contains scans | `LiteralSearchKernel.findSingleByteTail`, `LiteralSearchKernel.skipToContainsCandidate` | Regulator ([#155]), similar to memchr ([memchr.rs][memchr-generic]) |
| Call-free pair word scan | The literal's first and last bytes are tested a word at a time in a loop that makes no calls. Candidates are verified out of line with 8-byte word compares, two 4-byte reads, or single bytes. | Contains, dot-star, and ordered literals in Trino and LIKE; contains in every language | `LiteralSearchKernel.skipToContainsCandidate`, `LiteralSearchKernel.verifyContainsCandidates` | Regulator ([#28], [#33], [#80], [#118]), similar to memchr ([packedpair][memchr-packedpair]) |
| Short literal in two words | A literal of 1 to 16 bytes is compared as two overlapping words of the width that `shortLiteralWidth` picks. The reads skip `Slice` bounds checks. | LIKE equality, prefix, and suffix tests, interpreted and generated | `LiteralMatchKernel.shortLiteralWidth`, `LiteralMatchKernel.matchesShortLiteralAt` | Unknown; the unchecked reads are Regulator ([#153]) |
| SWAR constants on aarch64 | The SWAR low-bits constant is read from a field, because aarch64 C2 cannot encode it as an immediate. Generated LIKE reads its broadcast constants from fields on aarch64 and keeps them as constants on x86. | aarch64 | `LiteralSearchKernel.findContains`, `TrinoLikeKernelGenerator.LikeEmitter.broadcastOperand` | Regulator ([#18], [#28], [design][d-gen-like]) |

## Lazy DFA

The DFA is RE2's lazy DFA; its ported pieces are listed in
[RE2 optimizations used as ported](#re2-optimizations-used-as-ported). These rows
cover its tables and loops beyond them.

| Optimization | What it does | Applies when | Where | Origin |
|---|---|---|---|---|
| Object rows with an integer sidecar | Each state is an `Object[]` row in the heap table whose slots point at next rows, so a step is one load and a `null` slot leaves for the cold path. A parallel `int[]` holds each transition as a state offset with tagged sentinels and a match bit, for the cold path and the integer loops. | Every heap-table search | `Dfa.DfaInstance.stateReferences`, `Dfa.searchForwardContinuation`, `Dfa.DfaInstance.computeTransition` | Regulator, similar to RE2's pointer rows ([dfa.cc][re2-dfa]) |
| Divide-free row index | A row offset becomes a state index by a shift for the row width's power-of-two factor and a multiply by the inverse of its odd part. | Cold paths, and every match step when native access is off | `Dfa.DfaInstance.stateIndex`, `Dfa.DfaInstance.stateIndexMultiplier` | Regulator ([#149], [design][d-row-index]) |
| Bounded paired table | Composed two-byte transitions advance two bytes per load. The whole table is built when it fits 64 KiB; otherwise only two hot rows are paired, within 16 KiB. After 16 searches in a row that each cover fewer than 16 bytes, the DFA drops its paired rows until its cache resets. | Heap table, searches of at least 256 bytes, small graphs | `Dfa.searchForwardPairs`, `Dfa.DfaInstance.selectPairedRows`, `Dfa.DfaInstance.recordPairedSearch` | Regulator ([#9], [design][d-paired]) |
| Specialized step loops | One loop scans for a one-byte prefix and steps the DFA together, and anchored searches with an unfolded prefix of 16 bytes or more have their own integer loop. Hot loops are counted loops, so C2 can drop the safepoint poll on each step. | One-byte required prefixes; long anchored prefixes; hot loops | `Dfa.searchForwardPrefixAccelSingleByte`, `Dfa.searchForwardAnchoredLongPrefixInt`, `Dfa.searchAnchoredCandidate` | Unknown |
| Sampled self-loop scan | With 64 KiB left, the search samples its next 64 transitions, all already cached. If at least 90% are self-loops, it switches to a loop that checks "the next row is this row" before decoding. | End-anchored or full-match searches of at least 64 KiB outside the paired loop, as in `.*` runs | `Dfa.searchForwardSampledSelfLoops`, `Dfa.shouldSampleSelfLoopTransitions` | Unknown |
| Self-loop exit-byte scan | A non-matching state that loops on every byte except 1 to 3 exit bytes vector-scans to its next exit byte. Matching self-loops in longest-match and reverse searches are read by a scalar loop that keeps their row. | Byte-level loops such as `\C*` or Latin-1 `[^\n]*`, Vector API; matching self-loops without it | `Dfa.scanSelfLoopTransitions`, `Dfa.DfaInstance.selfLoopExitByteSet`, `Dfa.scanMatchingSelfLoopTransitions`, `Dfa.scanMatchingSelfLoopTransitionsBackward` | Unknown, similar to regex-automata DFA acceleration ([accel.rs][ra-accel]); keeping the row is Regulator ([#144]) |
| Empty match at the start | A nullable start state whose next byte cannot begin a match returns the empty match at once. | Nullable patterns | `Dfa.canReturnEmptyAtStart` | Unknown |
| Candidate-start cursor | The DFA steps to each start-byte or filter candidate and confirms it with an anchored traversal that reads matching self-loop runs in one scan. When the confirmations exceed a linear work budget, or one runs past 128 transitions, the search falls back to the forward and reverse searches. A matcher builds it when constructed; a literal alternation's matcher builds it on its first long search. | Reusable first-match matchers on variable-length patterns without anchors or assertions | `Dfa.createCandidateStartCursor`, `Dfa.searchAnchoredCandidate`, `RegexpMatcher.createLongSearchCandidateStartCursor` | Regulator ([#163], [design][d-candidate-cursor]) |
| Group-zero forward cursor | The forward DFA and its acceleration state are kept across a matcher's group-zero finds instead of being set up for every match. | Repeated `find` without captures | `Dfa.createGroupZeroForwardCursor`, `Dfa.searchGroupZeroForward` | Regulator ([design][d-forward-cursor]) |
| Lazy quit on Unicode word boundaries | In a program with a word boundary that decodes characters (Rust Unicode `\b`, Java and Trino `\b`), the DFA quits only when a state that needs any assertion meets a non-ASCII byte before or after it; elsewhere ASCII decides `\b`. The regex-automata lazy DFA quits on every non-ASCII byte instead ([hybrid/dfa.rs][ra-hybrid]). | Rust Unicode `\b` and `\B`; Java and Trino word boundaries | `Dfa.DfaInstance.computeTransition`, `Dfa.DfaInstance.quits` | Regulator ([#64], [#76]) |
| Quit streak | After 4 DFA quits in a row, a matcher skips the DFA for the rest of its input. | Programs whose DFA can quit next to non-ASCII bytes | `CompiledPattern.matchOnOrdinaryEngine`, `RegexpMatcher.findGeneral` | Regulator ([#64]) |
| Java and Trino word boundaries on the DFA | Java and Trino word boundaries run on the DFA instead of forcing the NFA. State flags decide them next to ASCII bytes, and the lazy quit hands non-ASCII neighbors to an engine that decodes characters. | Java and Trino `\b` and `\B` | `Dfa.dfaEmptyFlags`, `Dfa.DfaInstance.startFlags` | Regulator ([#76]) |
| Context start caches | Start states are cached per context: begin text, begin line, Trino line, after a word byte, after CR, after a non-ASCII byte, and after a non-word byte. Flags are built only on a cache miss. | Every language | `Dfa.DfaInstance.analyzeStart`, `Dfa.DfaInstance.crlfStartFlags` | Regulator ([#6], [#64]); base RE2 [O-DFA-014] |

## Native DFA table

With `--enable-native-access=ALL-UNNAMED`, the DFA can also keep its
transitions in native memory. This is memory, not native code, and the heap
table stays authoritative.

| Optimization | What it does | Applies when | Where | Origin |
|---|---|---|---|---|
| Absolute-pointer table | Each slot of a table in an automatic arena holds the 64-bit address of the next row, so a step is one dependent load plus an add; zero means uncomputed and defers to the heap table. | Route order | Compilation tries literal alternation and literal set, then builds the compiled pattern and picks begin-line, ordered literal, dot-star literal, exact literal, fixed-width byte, character class, or a generated class, falling back to the compiled pattern. ## Matcher API

`RegexpMatcher` reuses its search scratch across finds, and regions and results
avoid copying input bytes.

| Optimization | What it does | Applies when | Where | Origin |
|---|---|---|---|---|
| Matcher-owned workspaces | A matcher creates its OnePass, BitState, and NFA scratch on first use and reuses it across finds. The stateless `*Into` APIs allocate per call instead. | `RegexpMatcher` searches | `OnePass.Workspace`, `BitState.Workspace`, `Nfa.Workspace` | Regulator ([design][d-workspaces]) |
| Allocation-free regions | `reset` with a region sets bounds without creating a `Slice` view, and `MatchResult` keeps the caller's `Slice` with absolute offsets. | Region resets and results | `RegexpMatcher.reset`, `RegexpMatcher.toMatchResult` | Regulator ([design][d-regions]) |
| Group-zero matcher routes | A matcher of a capture-free pattern finds with the one-byte table while fewer than 64 bytes remain, with the span matchers, or with the class counter, before the general search. A literal alternation hands regions of 64 bytes or more to the program's search. | Patterns without capturing groups | `RegexpMatcher.find`, `RegexpMatcher.findSpanSearch` | Regulator ([#91], [#122], [#123]) |
| Skip the group clear | The ordinary engine writes every slot itself, so a matcher does not clear its groups first. The rare disjoint-suffix, whole-input-capture, and word-run matchers sit behind one flag, out of line. | Matcher finds on patterns without a specialized compiled-pattern class | `CompiledPattern.matchOnPreEngineMatcher` | Regulator ([#138]) |
| Caller buffers trimmed to the pattern | A caller buffer longer than the pattern's slots is searched through a temporary array of the program's capture slots, so OnePass, which picks its route by buffer length, still runs. | Buffers longer than the pattern's slots, when the program has at most 64 capture slots | `CompiledPattern.matchRegionInto` | Regulator ([#146]) |

## Compile time and memory

Compilation is bounded by the memory budget and plans every engine's memory
before matching starts.

| Optimization | What it does | Applies when | Where | Origin |
|---|---|---|---|---|
| 96 MiB default budget | The default planning budget is 96 MiB instead of RE2's 8 MiB, so large DFA graphs reset less often. | Default options | `Re2.Options.defaults` | Regulator ([design][d-memory]); base RE2 [O-RE2-001] |
| Retained-memory compile charge | Each instruction is charged before flattening and again as flattening emits it, and a flatten that exceeds the program's share stops. RE2 caps instruction allocation while compiling; flattening has no separate budget check, and the retained program is then deducted from the DFA budget. A program also remembers a budget at which its DFA failed to initialize, so later searches do not rebuild it. | Every compile | `CompilerState.finish`, `Prog.flatten`, `Prog.getCachedDfa` | Regulator ([#133]) |
| Optional plans yield to forward DFAs | Literal searches of up to 64 bytes outside Trino and required bytes give way when they would stop the first-match or longest-match DFA from initializing. The root-skipping literal set drops its skip unless both DFAs can initialize, and the transparent start literal needs both to keep their minimum memory. Other literal searches, scan plans, and other matchers reserve whenever they fit. Each DFA charges its start-byte tables before creating any state. | Those optional plans, and every DFA | `CompiledPattern.tryReserveBesideForwardDfas`, `Prog.leavesDfaMinimum`, `Dfa.DfaInstance.initializationMemory` | Regulator ([design][d-memory]) |
| OnePass tables sized from targets | OnePass node storage grows on demand, as in RE2, and is capped at one more than the distinct byte-range targets, so the tables end exactly sized. | Large Unicode classes | `Prog.onePassInitialNodeCapacity`, `Prog.computeOnePass` | Regulator ([#8], [#107]); base RE2 [O-1PASS-003] |
| Memoized program optimization | NOP elimination and AltMatch insertion cache each chain's answer, so shared chains are walked once. | Every program | `Prog.optimize`, `Prog.isNopChain`, `Prog.isMatch` | Regulator ([#40]); base RE2 [O-PROG-001] and [O-PROG-002] |
| Byte-map builder limits | After 32 merges, groups of up to three ranges already merged are skipped, and IDs of active byte classes are renumbered once the next ID exceeds 256. | UTF-8 and large Unicode classes | `Prog.computeByteMap` | Regulator ([#8], [#107]); base RE2 [O-PROG-003] |
| Hints per range run | A lone byte range gets its hint directly; recoloring runs only for runs of two or more ranges. | Every flatten | `Prog.computeHints`, `Prog.computeRunHints` | Regulator ([#8]); base RE2 [O-PROG-005] |
| Dominator pass elision | A bounded structural check skips the dominator pass when it would change nothing, as for non-nullable alternations of literals and classes. When the pass runs, its predecessor scan stops at an instruction that is already a root. | Programs of at least 1024 instructions | `Compiler.shouldSkipDominatorPass`, `Prog.markDominator` | Unknown; the root stop is Regulator ([#119]) |
| Array-backed compiler | Instructions live in a growable array, and the compiler walks the tree post-order on array stacks instead of a generic walker. One clone table, cleared in constant time, serves every Trino greedy nullable loop in a compile. | Every compile | `CompilerState.compileTree` | Regulator ([#8], [#42]) |
| Seeded compile-time hashing | Compile-time hash tables mix in a per-process random seed, so crafted patterns cannot force collisions in every process. | Every compile | `SeededHash.hash` | Regulator ([#116]); the mix is MurmurHash3 `fmix64` |
| Linear parsing and simplification | Concatenations buffer literal code points in an int array, factoring works through views and an explicit stack, an unchanged coalescing walk returns its input, and a failed POSIX `:]` search is remembered. | Long literal runs, deep alternations, many `[:` | `Simplifier.simplifyAlternateForParse`, `Simplifier.factorAlternationForParse`, `RegexpParser.Parser.tryParsePosixCharClass` | Regulator ([#8], [#39]) |
| Character-class building | Ranges append in constant time when ascending, insert by binary search, and merge in one pass, with out-of-order ranges sorted once. Nested bracket sets pass up with a negation flag, and when one set is much larger, it is edited by the smaller one's ranges. | Every class; nested Java and Trino classes and Rust set operations | `CharClassBuilder.addCharClass`, `CharClassBuilder.addPending`, `RuneRangeSet.union`, `RuneRangeSet.intersection` | Regulator ([#8], [#39]) |
| Linear literal analysis | Adjacent literals accumulate in one buffer, and concatenations refer to their children's elements, expanded once at the root. | Counted repetitions, nested concatenations | `ExpressionAnalysis.buildLiteralSequence` | Regulator ([#34]) |
| Match length computed once | Length facts are packed into one `int` computed from the normalized tree, and compilation reuses it; the suffix after a required prefix is analyzed separately. | Every compile | `MatchLength.analyze`, `CompiledPattern.build` | Unknown; computing it once for compilation to reuse is Regulator ([#8]) |
| Two-stage Unicode tables | Case folds and code-point flags live in 256-code-point blocks with a shared empty block, and ASCII folds use a 128-entry table. One word-character table serves every Unicode word-boundary pattern. | Case-insensitive patterns, properties, Unicode `\b` and `\w` | `CodePointTable.get`, `CodePointFlags.get`, `UnicodeGroups.WordFlags` | Regulator ([#16]) |
| Lazy and indexed Unicode data | Each Unicode database section is decoded once, on first use. Full case-fold tokens are looked up in sorted primitive arrays, starting only at tokens that begin with the folded rune. | The first pattern that needs a section; Trino `(?i)` | `UnicodeDatabase.SimpleCaseFolding`, `UnicodeFullCaseFold.Data.firstTokenIndex` | Regulator ([#8], [#23]) |
